P3b — レシピ別 ★（Resource KVP）

背景: 調理成功ごとにレシピ単位で ★ を加算し、サーバー Resource KVP で永続化。NUI はオープン時一括取得＋調理後プッシュで同期。上限は設けず表示のみ（パッシブ倍率は P3e）。

方針確定: ox_lib 非依存の GetResourceKvpInt / SetResourceKvpInt、jp-cooktree:requestStars、成功後 pushStarsToClient。

KVP キー形式（実装）

server/stars.lua 内: リソース名 + 正規化した識別子 + レシピ ID を連結（詳細はコード参照）。識別子は GetPlayerIdentifier(src, 0)、未取得時は noid:<src> フォールバック。

<GetCurrentResourceName()>:star:<safe_identifier>:<safe_recipeId>

P3c — ミニゲーム・分岐・確率クリティカル（現行）

ミニゲーム: モノレポの jp-glitch28（原作 GPL-3.0・日本語 UI）。他 MOD 互換でフォルダを glitch-minigames にリネームしている場合は Config.GlitchMinigamesResource と fxmanifest.lua の dependencies をその ensure 名に合わせる。クリティカル: Glitch の戻り値は boolean のみのため、Q-P3c-3 は案 C（成功後 Config.CriticalChance）で確定。perfect ゾーンは難易・演出用。

P3c 実機検証ログ（2026-05-11）

失敗経路（ミニゲーム失敗 → サーバー失敗分岐）

cook_test start recipe=omurice_special stages=1
Stage 1/1: （label は下記「文字化け」参照）
[SkillCheck] start() called
Sound loaded successfully: sound-failure
cook_test result success=false

インベントリに 失敗作（failed_dish） が付与されることを確認 → サーバー失敗分岐・submitCookResult 連携 OK。

成功経路（連続成功・重量計算）

sound-buttonPress
sound-click ×3
sound-success
cook_test result success=true

特製オムライスが複数回付与され、ox_inventory の重量表示（例: 300g×7=2.10kg）と整合することを確認。

軽微: print(stage.label) の「????」について

Windows コンソールのコードページ（CP932 等）で UTF-8 の日本語ログが化けることがある。ゲーム内 UI・データは UTF-8 のまま。対処は chcp 65001 等か、ログ用途で label を英字にするか（視認性低下のため任意）。動作不具合ではない。

P3d — 調理品 metadata（ox_inventory）

確定: Q-P3d β 相当＝アイテムに metadata。売却の実装は P3g（Config.SellPriceMultiplier は定数のみ先行）。NUI 通知なし。重量は ox 側定義のまま。失敗作にも同スキーマで quality='failed'。

-- 通常成功
{ quality = 'normal', star = false, cookedBy = string, cookedAt = unix }

-- クリティカル
{ quality = 'critical', star = true, cookedBy = string, cookedAt = unix }

-- 失敗
{ quality = 'failed', star = false, cookedBy = string, cookedAt = unix }

変更: fxmanifest.lua version 0.7.1。config/config_main.lua に SellPriceMultiplier。server/inventory.lua の AddItem(src, item, count, metadata?)。server/main.lua でクリティカル抽選後に付与（metadata と品質一致）。ログ: quality=normal / quality=critical / quality=failed。

実機確認: インベントリ inspect で metadata、クリティカルは確率のため複数回試行。
