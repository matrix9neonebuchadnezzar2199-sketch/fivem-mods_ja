# 2026-05-10 polapaint v2.0 再構築

## 時刻メモ

セッション内実装（ローカル日付 2026-05-10）。

## 概要

- `polapaint_old` は凍結前提とし、`polapaint` を **v2.0（ローカルストレージ・セッショントークン・bridge）** としてゼロから再構成した。
- 仕様: `config.lua`・`shared/util.lua`・`server/storage.lua`（保存・署名 GET）・`server/main.lua`（統合 HTTP・撮影/編集 POST・QB CreateUseableItem）・`client`・`html`・`snippets`・`README.md`。
- 画像は `data/photos/*.jpg`（`.gitignore`）、Webhook は `polapaint_webhook` convar。
- NUI アップロードは **`https://<resource>/uploadCapture` / `uploadEdit`**（CEF → リソース HTTP ハンドラ）。誤っていた `http://GetCurrentServerEndpoint/...`（クライアントでは無効・Mixed Content 等）は撤回済み。
- `SetHttpHandler` は **`server/main.lua` にのみ**登録。リソース間競合ではなくリソース名ルーティング。
- POST 本文は `setDataHandler` 内で結合し、`Content-Length` がある場合はチャンク足りるまで待機。クエリは `req.path` / `req.url` の両方からフォールバック。
- `polapaint_old/fxmanifest.lua` → **`fxmanifest.lua.disabled`**（リソース二重認識防止）。

## 追記（JSON + base64 アップロード・2026-05-10）

- NUI → `SetHttpHandler` は **`fetch('https://' + GetParentResourceName() + '/uploadCapture|uploadEdit')`** に統一。本文は **`application/json`**、`image` に JPEG の **base64**。サーバーで `PolaPaintUtil.b64decode` → 既存 `handleUpload*`。
- バイナリ直 POST・`X-Polapaint-*`・`NUI_ORIGIN` ワークアラウンド・F2 診断キーは撤回。
- OPTIONS の `Access-Control-Allow-Headers` は **`Content-Type`** のみ。
- POST 本文は `setDataHandler` で結合。`Content-Length` があるときは足りるまで待機。無い環境向けに短い **debounce（120ms）** を残す。本文上限は base64 膨張を見込み **`maxBytes * 1.4 + 64KiB`** 前後。

## 追記（base64 デコード高速化・2026-05-10）

- 旧 `b64decode`（`gsub` 二段のビット列展開）は大容量で **メインスレッド長時間ブロック**し HTTP 応答が遅延するため、`string.byte` / `table.concat` / Lua 5.4 ビット演算の **高速デコード**に差し替え。
- `hasControl` に **`type(s) ~= 'string'`** ガード。
- 検証ログ `[polapaint] capture upload received: bytes=… token=…` は **`Config.Debug`** 時のみ（`edit` も同様）。

## 追記（NUI → RegisterNUICallback → net event・2026-05-10）

- アップロードは **`SetHttpHandler` の POST では届かない**ため、`uploadCapture` / `uploadEdit` を **`RegisterNUICallback`（client）→ `TriggerServerEvent`（server）** に変更。HTTP ハンドラは **GET（写真配信）のみ**。
- `close` / `ppNuiAlert` の **`cb` は `{ ok = true }`** を返す（応答停滞防止）。

## 追記（v3・撮影を ox_lib + net event のみ・2026-05-10）

- 撮影: **トークン／`prepareCapture` NUI を廃止**。`screenshot-basic` → **`lib.inputDialog`** → **`TriggerLatentServerEvent`** で `uploadCapture`（大容量対応）。
- 編集: `savePaint` NUI コールバックのみ `fetch` → **`TriggerLatentServerEvent`** で `uploadEdit`。
- `SetHttpHandler`: **GET のみ**（変更なし）。
- `fxmanifest`: **`ox_lib` / `screenshot-basic` を dependencies に明示**。`shared_scripts` 先頭に `@ox_lib/init.lua`。

## 追記（撮影フロー診断 STEP ログ・2026-05-10）

- `client/main.lua`: `notify` を **`[polapaint client]`** プレフィックスで F8 に必ず出力。`startCaptureFlow` に **STEP1〜STEP7 / STEP_TIMEOUT / STEP2.5** の `print` を追加（原因切り分け用・安定後に削除可）。

## 追記（写真ストレージ・256 シャード・2026-05-10）

- `server/storage.lua`: 保存パス **`data/photos/<2桁hex>/<32hex>.jpg`**（起動時に 256 サブディレクトリへ `.keep` 作成）。**旧 `data/photos/<id>.jpg` は `loadPhoto` でフォールバック**。
- `.gitignore`: シャード配下の `*.jpg` と `.keep` を無視。

## 追記（TriggerLatentServerEvent・大容量 JPEG・2026-05-10）

- 約 **1.5MiB 級の base64** は通常の `TriggerServerEvent` でサーバーに届かないことがあるため、**`uploadCapture` / `uploadEdit` を `TriggerLatentServerEvent`**（`NET_IMG_LATENT_BPS = 2097152`）。サーバーは **`RegisterNetEvent` のまま**。

## 追記（SaveResourceFile と JPEG バイナリ・2026-05-10）

- `savePhoto`: `SaveResourceFile(..., bin, #bin)` を **`..., bin, -1`** に変更（JPEG に NUL が含まれる場合の書き込み失敗回避）。

## 追記（シャード書込失敗→フラットへフォールバック・2026-05-10）

- 環境により **`data/photos/<shard>/<id>.jpg` が `write_fail`** となる事例への対策: 保存直前に **`data/photos/<shard>/.keep`** を再作成し、それでも失敗したら **`data/photos/<id>.jpg`** に再試行。

## 追記（givePhoto / ox アイテム未定義の案内・2026-05-10）

- `notify_capture_item_not_defined` は多くの場合 **`ox_inventory:AddItem` 失敗**（**`polaroid_photo` が ox の items に無い**）。`givePhoto` に **`no_framework`**、`uploadCapture` に **Debug 時の失敗ログ**、README に **トラブルシュート** を追加。
