## 追記 — ox_inventory スタック／原作との保存フロー／画像＋ロック（分析メモ）

### スタックの仕組み（ox_inventory 側の要点）

- **スタック可能**なアイテムは `items.lua` で **`stack = true`**。`AddItem` 時は **`Items.Metadata`** がメタを正規化したうえで、既存スロットと **`table.matches(metadata, …)`** が一致すれば **同じスロットに加算**される（`modules/inventory/server.lua` の `Inventory.AddItem`）。
- **一致しない典型**: (1) `stack = false`、(2) メタが毎回違う（`degrade` 由来の `durability` がタイムスタンプになる等）、(3) 片方が `{}`、片方が `nil` 扱いの差として蓄積した微妙な差、(4) 空 `{}` を「メタあり」とみなす経路。
- **jp 側で入れた対策の経緯**: `INV.AddItem` の **`{}` → `nil` 正規化**、`createItem` フックで **`paper_blank` は常に `{}` 返却**（余計なメタを剥がす）、`INSTALLATION_JP` の **`stack = true` / `degrade` 禁止**の明記。それでも配布が毎回 **新スロット**に落ちる場合があるため、**v2.0.3-jp.10** で配布時に **`Search(..., 'slots')` → 空メタのスロットがあれば `AddItem(..., slot)`** で明示的に足す **`INV.TryStackBlankPaperOx`** を追加した。

### 「paper_blank」の仕様と、なぜ原作・手順ではスタック不可に見えたか

- **原作（alnd029/b2b_documents）**の README では画像は **「URL で挿入」**（ローカルファイルや base64 前提ではない）。インストール手順の **サンプル `items.lua` は `stack = false`** を採用していた（本フォーク初期の `INSTALLATION_JP.txt` も同様に写していた）。
- **`stack = false` にしていた推測理由**（コードに明示コメントはないが、設計としてあり得る説明）:
  - **RP 上「1 枚＝1 スロット」**の見せ方（紙束の重なりを UI 上は分けたい等）。
  - **フレームワーク横断**の手順書で、ESX / QB / ox の差を吸収するため **最も安全なデフォルト（非スタック）**に寄せた。
  - 当時の **ox_inventory の挙動やメタ生成**に依存せず、「1 アイテム＝1 インスタンス」でトラブルを減らす意図。
- **本フォークの方針**: 白紙は **空メタのコモディティ**として扱い、**スタック可**に寄せる（運営・プレイヤー要望）。そのため **`stack = true`** 推奨＋コード側のメタ正規化と **明示スタック配布**まで踏み込んだ。

### 原作と jp の「保存／ロック」ボタン以降のフロー比較

| 段階 | 原作（想定・一般的な b2b 系） | jp フォーク（改修後） |
|------|-------------------------------|------------------------|
| NUI | `triggerAction` → `quill.root.innerHTML` をそのまま `content` に載せて `fetch doAction` | `b2bSerializeDocForSave()`：**原則 Delta JSON**（`__B2B_DOC_QV1__` + `JSON.stringify({ops})`）。**ops 空・stringify 失敗・JSON が約 900KB 超**なら **`__B2B_DOC_HTML_V1__` + innerHTML**。`content` が string でないと **サーバーが拒否**。 |
| クライアント | `RegisterNUICallback('doAction')` → `lib.callback.await('b2b_documents:handleAction', …)` | 同じ。 |
| サーバー | `data.content` を DB の `LONGTEXT` に保存、`lock` 時は `locked=1` とメタ更新 | 同じ＋**`content` の型チェック**を追加。 |

**差分の評価（画像＋ロックが失敗し得た理由）**:

- 原作は **HTML 1 本**で、画像が URL なら **本文が軽い**。jp で **base64 を Delta または HTML に直埋め**すると、**`fetch` の JSON ボディが数 MB 級**になり、**FiveM NUI の受信上限や JSON パース**で **`data.content` が壊れる／nil になり `handleAction` が false**、あるいは **MySQL `max_allowed_packet`** で失敗し得る。
- **v2.0.3-jp.9** で巨大 Delta は **HTML フォールバック**にしたが、**HTML も base64 だらけだと同様に巨大**なので根本は **画像データ量の削減**が必要。**v2.0.3-jp.10** で挿入時に **リサイズ＋JPEG 化**してロック時のペイロードを抑える。

### 実装メモ（v2.0.3-jp.10）

- **`INV.TryStackBlankPaperOx`**: `ox_inventory:Search(src, 'slots', Config.Items.blank)` を `pairs` で走査し、**`metadata` が空**のスロットに **`AddItem(src, blank, 1, nil, slot)`**。（**v2.0.3-jp.11 で撤回** — 下記参照）
- **`b2bShrinkImageDataUrl`**: 挿入直前に **最大辺 1280・JPEG 0.82**（透明は白背景に落とす）。

**Git**: `fix(jp-b2b_documents): ox blank stack via Search+slot AddItem, image shrink for lock v2.0.3-jp.10`（`git log --oneline --grep=jp.10` 等で確認）

## 追記 — v2.0.3-jp.11（白紙スタック撤回・画像ボタン CEF 修正）

### 方針変更（スタック）

- **白紙の明示スタック配布（`INV.TryStackBlankPaperOx`）は撤回**。ox の版差・環境で安定しないため運用判断で諦め、配布は **`INV.AddItem` のみ**に戻した（`inventory_bridge.lua` / `server.lua`）。
- **`createItem` フック**による `paper_blank` メタの `{}` 正規化は維持。
- **`INSTALLATION_JP.txt`**: `stack = true` でも白紙が別スロットに落ちることがある旨を明記し、**本リソースはスタックを保証しない**。

### 不具合: 1 枚目の白紙では画像挿入できるが、次の白紙以降は画像ボタンが無反応（`ensure` しても直らないことがある）

- **原因**: Quill 2 のツールバー実装（`modules/toolbar.js`）は、ボタンの **`click` で先に `this.quill.focus()`** を実行し、その**後**に `handlers.image`（従来のカスタムハンドラ）が呼ばれる。FiveM NUI（CEF）では、**ユーザー操作トークンが `focus` で消費**され、ハンドラ内の **`input.click()` が無視**されることがある（プログラムからのファイルダイアログ起動がブロックされる）。
- **対策**: ツールバー容器に **`click` キャプチャ**を 1 度だけ付け、`button.ql-image` を検知したら **`preventDefault` + `stopImmediatePropagation`** で Quill のリスナより先に処理し、**その場で**常設の **`#b2b-doc-image-file`** に `value` を空にしてから **`input.click()`**。`closeUI` でファイル input をリセット（`ui/index.html` / `ui/script.js`）。

**Git**: `b30a8aa` — `fix(jp-b2b_documents): image pick via click capture for CEF; remove ox stack helper v2.0.3-jp.11`

## 追記 — 2026-05-09（ox_inventory hooks: `mt` nil / lua54）

### 現象

- サーバーログ: `@ox_inventory/modules/hooks/server.lua:95: attempt to index a nil value (local 'mt')`（行番号は版差あり）。

### 原因

- `ox_inventory` の `exports.registerHook` は `local mt = getmetatable(cb)` の直後に `mt.__index` を触る実装になっている。
- **`lua54 'yes'`** では、**素の Lua 関数**にメタテーブルが付かないため `mt` が **`nil`** になり得る。
- 本リソースの **`createItem` 白紙メタ正規化**が無名関数で `registerHook` しており、該当した。

### 対応

- フックを **`setmetatable({}, { __call = function(_, payload) ... end })`** として登録。`getmetatable(cb)` が非 `nil` になり、かつ `cb.resource` / `cb.hookId` をフックオブジェクト（テーブル）へ載せられる。

### リリース

- **v2.0.3-jp.12**（`fxmanifest.lua` / `CHANGELOG.md` / `server.lua`）。
