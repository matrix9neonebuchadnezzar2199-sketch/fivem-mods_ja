==========================================================
  jp-b2b_documents（b2b_documents 日本語版）— インストール
==========================================================

【必須】
  - ox_lib
  - oxmysql

【インベントリ（いずれか 1 つ）】
  - ox_inventory（推奨: metadata 対応）
  - qb-inventory（info を metadata 相当として利用）
  - ESX 標準インベントリ（metadata 非対応のため b2b_documents_links を自動作成）

【ターゲット（任意）】
  - ox_target（推奨）
  - qb-target
  - どちらも無い場合は配布拠点で [E] キー（距離フォールバック）

【フレームワーク（自動検出）】
  - es_extended / qb-core / qbx_core

※ 下記の <RESOURCE> は「置き換え前の記号」です。items.lua や server.cfg に
  **<RESOURCE> とそのまま書かないでください**（エラー: No such export usePaper in resource <RESOURCE>）。
  フォルダ名が例えば jp-b2b_documents なら、すべて **jp-b2b_documents** に置換します。
  server.cfg の ensure 名と、ox_inventory の export / nui:// の名前を一致させてください。

----------------------------------------------------------
STEP 1：データベース（未実施だと保存・ロックが必ず失敗します）
----------------------------------------------------------
  sql/b2b_documents.sql を、**oxmysql が接続しているのと同じデータベース**（例: fivem_db）
  にインポートする。下記のどれか **1 つ** で SQL を実行すればよい（全部必須ではない）。

  --- 「phpMyAdmin」って何・どこ？（よくある誤解）---
  FiveM や本 MOD に **付いているツールではありません**。MySQL をブラウザで操作する **別のプログラム**の名前です。
  - **レンタルサーバ / VPS の管理画面**（例: Plesk、cPanel）に「phpMyAdmin」リンクがある場合 → そこから開く（URL は業者ごとに違う）。
  - **XAMPP 等**を入れているローカル環境では `http://localhost/phpmyadmin` などであることが多い（入れていなければ存在しない）。
  - **自分の PC に無いなら無視してよい**。代わりに **HeidiSQL** だけ使えば十分です。

  --- Windows ローカル向けのおすすめ（HeidiSQL）---
  無料・単体インストール: https://www.heidisql.com/
  インストール後、新規セッションで **ホスト（多くは 127.0.0.1）・ユーザー・パスワード・ポート** を、
  `server.cfg` の **mysql_connection_string** と同じ値にして接続 → 下の「HeidiSQL の場合」の手順へ。

  コンソールに次のように出る場合はテーブル未作成のままです:
    Table 'fivem_db.b2b_documents' doesn't exist
  → 上記 SQL をその DB 名で実行し直し、`restart jp-b2b_documents` する。

  ESX 標準インベントリを使う場合、b2b_documents_links は初回起動時に自動作成されますが、
  **b2b_documents 本体のテーブルは本 SQL のみ**（自動では作りません）。

  --- DB 名の確認（どれに入れればいいか）---
  FiveM の server.cfg にある **set mysql_connection_string**（または oxmysql の接続設定）を開く。
  文字列の中に **database=...** または **dbname=...** や **/fivem_db** のように「DB 名」が書いてある。
  エラーが `fivem_db.b2b_documents` なら、その **fivem_db** が正しい入れ先。

  --- phpMyAdmin を「すでに使える環境」にいる場合のみ ---
  1. ブラウザで phpMyAdmin を開く（上記の管理画面 URL など）。
  2. 左の縦一覧に **データベース名**（例: fivem_db）が並ぶ。**その名前をクリック**するだけで「その DB を選んだ」状態になる。
  3. 上メニュー「SQL」を開き、`b2b_documents.sql` の中身をすべてコピーして貼り付け、「実行」を押す。
     （「インポート」タブから .sql ファイルを選んでもよい）

  --- HeidiSQL の場合 ---
  1. HeidiSQL でサーバーに接続する。
  2. 左のツリーで **データベース名**（例: fivem_db）を **1 回クリック**して選択（ハイライト）する。
  3. メニュー「ファイル」→「SQL ファイルを実行」で `b2b_documents.sql` を選ぶ。または「クエリ」タブに SQL を貼って F9 で実行。

  「選択」とは、**その DB の中にテーブルを作る対象を決める**という意味。左で別の名前（mysql や information_schema など）を選んでいないかだけ確認すればよい。

----------------------------------------------------------
STEP 2：配置
----------------------------------------------------------
  本フォルダを resources 配下に置き、server.cfg に（例: フォルダ名が jp-b2b_documents のとき）:
      ensure jp-b2b_documents

----------------------------------------------------------
STEP 3：アイテム登録
----------------------------------------------------------

【ox_inventory】
  ox_inventory/data/items.lua に追記する。
  同一の return { ... } テーブル内で、このあとに別アイテム（例: ['bandage']）が続く場合は、
  **各ブロックの閉じを必ず `},`（カンマ付き）にする**。`}` だけだと Lua 構文エラーになる。

  以下は **フォルダ名が jp-b2b_documents のときの完成例**（コピーするなら <RESOURCE> を自分の名前に読み替え）:

  ['paper_blank'] = {
      label = '白紙の用紙', weight = 10, stack = false, close = true,
      client = {
          image = 'nui://jp-b2b_documents/web/images/paper.png',
          export = 'jp-b2b_documents.usePaper'
      }
  },
  ['document'] = {
      label = 'ドキュメント', weight = 10, stack = false, close = true,
      client = {
          image = 'nui://jp-b2b_documents/web/images/document.png',
          export = 'jp-b2b_documents.usePaper'
      }
  },

【qb-inventory】
  qb-core/shared/items.lua 等に paper_blank / document を追加し、
  qb-inventory/html/images/ に paper.png / document.png を配置。
  本リソースの server が CreateUseableItem を登録します（ox_inventory 未使用時）。

【ESX 標準】
  データベース items テーブルに paper_blank / document を追加し、
  limit 等をサーバー方針に合わせて設定。

----------------------------------------------------------
STEP 4：config.lua
----------------------------------------------------------
  Config.Locale / Config.Framework / Config.Inventory / Config.UseOxTarget
  Config.PaperCooldown / Config.DistributionPoints を調整。

  NotoSerifJP-Bold.woff2 を配置（fonts.css を参照）。

==========================================================
  ESX 標準インベントリの制約
==========================================================
  同一プレイヤーが複数の「ドキュメント」を所持する場合、
  どのインスタンスを開いたか厳密には区別できません（リンクは「最新1件」推定）。
  厳密運用が必要な場合は ox_inventory 等の metadata 対応インベントリを推奨します。
