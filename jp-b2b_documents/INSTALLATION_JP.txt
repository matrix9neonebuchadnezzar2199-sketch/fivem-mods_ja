==========================================================
  jp-b2b_documents（b2b_documents 日本語版）— インストール
==========================================================

【必須】
  - ox_lib
  - oxmysql

【インベントリ（いずれか 1 つ）】
  - ox_inventory（推奨: metadata 対応）
  - qb-inventory（info を metadata 相当として利用）
  - ESX 標準インベントリ（metadata 非対応のため b2b_documents_links を自動作成）

【ターゲット（任意）】
  - ox_target（推奨）
  - qb-target
  - どちらも無い場合は配布拠点で [E] キー（距離フォールバック）

【フレームワーク（自動検出）】
  - es_extended / qb-core / qbx_core

※ 下記の <RESOURCE> は「置き換え前の記号」です。items.lua や server.cfg に
  **<RESOURCE> とそのまま書かないでください**（エラー: No such export usePaper in resource <RESOURCE>）。
  フォルダ名が例えば jp-b2b_documents なら、すべて **jp-b2b_documents** に置換します。
  server.cfg の ensure 名と、ox_inventory の export / nui:// の名前を一致させてください。

----------------------------------------------------------
STEP 1：データベース（通常は何もしなくてよい）
----------------------------------------------------------
  **リソース起動時に `b2b_documents` テーブルが無ければ自動で作成**します（oxmysql 接続先 DB 上）。
  HeidiSQL 等で手動インポートは **不要** です。

  `sql/b2b_documents.sql` は、DBA がレビュー用に中身を見る・別手段で流す場合の **参照用** として残しています。

  まだ `Table '...b2b_documents' doesn't exist` と出る場合の例:
  - MySQL ユーザーに **CREATE** 権限がない（ホスティングで DDL 禁止など）→ 権限を付与するか、管理者に sql の実行を依頼
  - **oxmysql がまだ起動していない / 接続文字列が違う** → server.cfg の mysql 設定を確認し `restart oxmysql` から

----------------------------------------------------------
STEP 2：配置
----------------------------------------------------------
  本フォルダを resources 配下に置き、server.cfg に（例: フォルダ名が jp-b2b_documents のとき）:
      ensure jp-b2b_documents

----------------------------------------------------------
STEP 3：アイテム登録
----------------------------------------------------------

【ox_inventory】
  ox_inventory/data/items.lua に追記する。
  同一の return { ... } テーブル内で、このあとに別アイテム（例: ['bandage']）が続く場合は、
  **各ブロックの閉じを必ず `},`（カンマ付き）にする**。`}` だけだと Lua 構文エラーになる。

  以下は **フォルダ名が jp-b2b_documents のときの完成例**（コピーするなら <RESOURCE> を自分の名前に読み替え）:

  ['paper_blank'] = {
      label = '白紙の用紙', weight = 10, stack = false, close = true,
      client = {
          image = 'nui://jp-b2b_documents/web/images/paper.png',
          export = 'jp-b2b_documents.usePaper'
      }
  },
  ['document'] = {
      label = 'ドキュメント', weight = 10, stack = false, close = true,
      client = {
          image = 'nui://jp-b2b_documents/web/images/document.png',
          export = 'jp-b2b_documents.usePaper'
      }
  },

【qb-inventory】
  qb-core/shared/items.lua 等に paper_blank / document を追加し、
  qb-inventory/html/images/ に paper.png / document.png を配置。
  本リソースの server が CreateUseableItem を登録します（ox_inventory 未使用時）。

【ESX 標準】
  データベース items テーブルに paper_blank / document を追加し、
  limit 等をサーバー方針に合わせて設定。

----------------------------------------------------------
STEP 4：config.lua
----------------------------------------------------------
  Config.Locale / Config.Framework / Config.Inventory / Config.UseOxTarget
  Config.PaperCooldown / Config.DistributionPoints を調整。

----------------------------------------------------------
STEP 5（任意）：オフライン用フォント
----------------------------------------------------------
  ui/fonts/ に NotoSansJP-Regular.woff2 / NotoSansJP-Bold.woff2 /
  NotoSerifJP-Bold.woff2 を配置（fonts.css を参照）。

==========================================================
  ESX 標準インベントリの制約
==========================================================
  同一プレイヤーが複数の「ドキュメント」を所持する場合、
  どのインスタンスを開いたか厳密には区別できません（リンクは「最新1件」推定）。
  厳密運用が必要な場合は ox_inventory 等の metadata 対応インベントリを推奨します。
