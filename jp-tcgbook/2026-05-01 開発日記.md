#### A-0. 編成デッキ（10枚）と対戦手札（5枚）の関係

| レイヤー | 枚数 | 備考 |
|----------|------|------|
| **デッキ編成** | **10枚** | `Config.DeckSize`。使用デッキは10枚揃いのみ |
| **対戦1試合で使うカード** | **各プレイヤー手札5枚** | 盤9マス・先攻5枚／後攻4枚配置のため**ドロー山札は無い**（ベースルール） |
| **編成10枚→対戦5枚** | **決定済** | **§「A-0 決定（2026-05-01）」** を正とする（サーバー側シャッフル後の**先頭5枚**。プレイヤー試合前指定なし） |

先決・乱数・配置・奪取・勝敗計算はすべて **サーバー権威**。クライアントはリクエスト送信と同期表示のみ。

#### A-0 決定（2026-05-01）

**採用案: (a) サーバーがシャッフル後、先頭5枚を対戦手札にする。**

- **生成主体**: サーバー（`battle_pvp.lua` および `battle_debug.lua` 共通）
- **入力**: 使用デッキ（`is_active=true`、10枚揃い）
- **手順**: Fisher–Yates でサーバー側シャッフル → **先頭 5 枚**を対戦手札、残り 5 枚は **本試合では未使用**（ベースルールに山札なし）
- **乱数**: サーバー側 `math.random`（PHASE 2b では追加要件なし。将来不正対策で `crypto` 系に切り替え可）
- **NUI 表示**: 試合開始時、自分の手札 5 枚のみ表示。残り 5 枚は表示しない
- **採用理由**:
  1. 実装最小（現 `battle_debug.lua` と同方針）で CPU 戦と本番 2 人戦の経路が揃う
  2. A-9「敗北時コピー」のプールが自動的に **参戦5枚**で確定し、別議論を省ける
  3. プレイヤーの試合前選択操作が不要 → 仮想ロビーから対局開始までの UX が単純

**A-9 関連項目の同時確定**:
- **敗北時コピーのプール**: **参戦 5 枚**（編成10枚全体ではなく、サーバーが選んだ 5 枚から 1 枚ランダム）
- **編成10→5 枚の選び方**: A-0 の通り（プレイヤー指定なし）

#### A-1. 数値レンジと DB の対応

- ルール上の強さ: **1〜9** と **A（10段階の最大）**。
- **本 MOD のマスタ**は四方向を **数値 1〜10** で保持する想定。**A は 10 と同一**（UI 表示のみ `A` にしてよい）。

#### A-2. ゲームの準備（コンポーネント）

1. **盤面（ボード）**: **3×3**、計 **9マス**。
2. **手札**: 各プレイヤー **5枚**（※上記 A-0 のとおり、編成10枚から選ばれた結果としてサーバーが配る）。
3. **カード属性**: 各カードに **上・下・左・右** の強さ（上記レンジ）。
4. **所有権**: 盤上の各マスは「どちらのプレイヤーの色か」を保持する。UI は **枠色**などで区別（例: 自分青／相手赤）。線が細い場合は太さ調整は後続で可。

#### A-3. ゲームの進行（ターン制）

1. **先攻／後攻**をランダム（またはコイントス相当のサーバー乱数）で決定する。
2. 自分のターンに、手札から **1枚**選び、盤面の **空マス**に配置する。
3. 配置した **直後**に **バトル（判定）** を行う（A-4）。
4. 判定終了後に相手のターンへ。**9マスがすべて埋まる**まで交互に繰り返す。  
   **必ず先攻が5枚目・後攻が4枚目を置いた時点で終了**（計9手）。

#### A-4. バトル（ひっくり返し判定）— コアロジック

| 項目 | 内容 |
|------|------|
| **発生タイミング** | **今置いた1枚**を置いた直後、**そのマスに上下左右で隣接するマス**についてだけ見る |
| **判定対象** | 隣接マスに **相手所有**のカードがある場合のみ、その **接している辺同士**で数値を比較する |
| **勝ち（奪取）** | **自分（配置したプレイヤー）の辺の数値 ＞ 相手の辺の数値** のとき、その隣のマスのカードの **所有権を配置プレイヤーに変更**する（ひっくり返す）。UIは枠色を更新 |
| **負け・同値** | **＜** または **＝** のときは **何もしない** |
| **攻撃元の制限** | **そのターンに置いたカードからしか攻撃しない**。既に盤にあった自分のカードからは追加判定しない |
| **連鎖** | **なし**（コンボ等特殊ルールは採用しない限り、**この配置で発動する判定は1回分で完結**。ひっくり返ったカードはこのターン中にさらに隣を攻撃しない） |
| **複数隣接** | 十字などで **複数の相手カードに同時に隣接**した場合、**各辺ごとに独立に**比較し、勝っている相手マスは **すべて**奪取してよい |

#### A-5. 勝敗の決定

- **終了**: 9マスすべてにカードが置かれた時点。
- **スコア**: **（盤面で自分の色になっているマス数）＋（手札に残っている自分のカードの枚数）** の合計。
  - 初期は各5枚なので、終盤は **片方が手札1枚・もう片方0枚**などになりうる。
  - **例**: **6 対 4** のように過半数を取った側が勝ち。
  - **5 対 5** は **ドロー（引き分け）**。

#### A-6. 開発者向け：実装アルゴリズム（疑似コード）

```
  checks = [
    (r - 1, c, placed.stat_top,    'stat_bottom'),  // 上隣の「下辺」と接する
    (r + 1, c, placed.stat_bottom, 'stat_top'),
    (r, c - 1, placed.stat_left,   'stat_right'),
    (r, c + 1, placed.stat_right,  'stat_left'),
  ]
  for (nr, nc, myStat, oppKey) in checks:
    if nr, nc out of 0..2: continue
    tgt = cell[nr][nc]
    if tgt empty or tgt.owner == player: continue
    oppStat = tgt.card[oppKey]
    if myStat > oppStat:
      tgt.owner = player

  // ベースルール: このターンでひっくり返したマスからの連鎖判定は行わない
```

クライアント向けには、サーバーが **更新後の盤面オーナー行列・手札枚数・ターン** を同一イベントで返すと同期が単純。

### 7. ゲームルール（デッキ／カード）要点

- 1デッキ **10枚**、1プレイヤー最大 **10デッキ**

- カードは四方向 **1〜10**（UI では最大を **A** 表示可）。対戦の**盤上ルール**は **冒頭「PHASE A」**（手札各5・配置後に隣のみ判定・連鎖なし・終了時スコアは盤の自色＋手札残）

### 17. デバッグ用ロビー・CPU対戦（一連動作確認）

**目的**: 本番PvPや実プレイヤー検索なしで、BOOK 対戦タブから **検索→対戦開始→手札選択→配置→CPU自動手→終了** までを通す。

**前提**

- **`Config.DebugCommands == true`** のときのみ有効（本番では `false` で UI もサーバーも無効）。
- **`openBook`** の `data.ui.allow_debug_battle` で NUI にデバッグロビー表示可否を渡す。
- **本番の仮想ロビー（`battle_lobby.lua`）とは別セッション**。CPU対戦中は仮想ロビー操作を拒否し、逆も同様。

**サーバー（`server/battle_debug.lua`）**

- **ルール**: 設計書 **PHASE A**（隣接辺比較・配置直後のみ奪取・**連鎖なし**）。
- **lookup**: `jp-tcgbook:server:battleDebugLookupId` — **オンライン確認はせず**、正の整数IDなら「検証用」表示名で OK を返すのみ。
- **開始**: `battleDebugStartCpu` — 使用デッキから **HandSize 枚**をシャッフルして人間手札、CPU はマスタからランダム **HandSize 枚**。先攻は乱数。先攻CPUなら即1手ランダム。
- **着手**: `battleDebugPlace` — `cell_index` 1〜9、`hand_index` **0始まり**。人間の後に CPU が1手ランダム。
- **終了**: `battleDebugLeave`、または **`battleVirtualLeave`（BOOK閉じる）** 内で `BattleDebugLeave` → クライアントへ `battleDebugEnded`。
- **状態復元**: `openBook` の **`battleCpuSession`** に現在盤を載せ、NUI が `AppState.battleCpu` に復元。

**クライアント / NUI**

- **イベント**: `battleDebugState`（都度）、`battleDebugLookupAck`、`battleDebugEnded`；マッチ通知は既存の **`virtualBattleMatched`** に **`is_cpu: true`**（`peer_server_id` は `nil`）。
- **コールバック**: `battleDebugLookupId` / `battleDebugStartCpu` / `battleDebugPlace` / `battleDebugLeave` → 上記サーバーイベント。
- **`jpTcgbookConfirmIfVirtualBattle`**: 仮想対戦接続に加え、**デバッグCPU対戦進行中**も `confirm` 対象（BOOK閉じ・終了ボタン）。

**ブラウザ単体**: `mock_data.js` が同系の状態機械と `postMessage` で **同等のメッセージ**を送り、UIだけ確認可能。

### 17b. 疑似 PvP モード（ソロ実機検証）

- **目的**: 実 FiveM 上で **1 クライアントだけ**でも PHASE 2b の **本番経路**（`battle_pvp.lua`）を検証する。
- **起動**: 対戦タブのデバッグ用ロビー（**`Config.DebugCommands == true`** かつ `allow_debug_battle` で UI 表示時のみ）から **「疑似 PvP 対戦を開始」**。NUI → `battlePvpStartSolo` → `jp-tcgbook:server:battlePvpStartSolo`。
- **経路**: `server/battle_pvp.lua` の **本物のセッション**（CPU 戦の `battle_debug.lua` とは別）。イベント名は本番 PvP と同一（`battlePvpStarted` / `battlePvpState` / `battlePvpPlace` / `battlePvpEnded` / `battlePvpError` 等）。
- **仮想相手**: サーバー内部で `src = -1`（`VIRTUAL_SRC`）。クライアントへの `TriggerClientEvent` は行わない。手番が仮想側のとき **サーバー AI** が `Citizen.SetTimeout(500, …)` 後に着手（**空マスランダム + 手札先頭＝hand_index 0**）。
- **検証可能項目**: PHASE 2b 受け入れのうち **「2 クライアントで 1 局完走」以外**（不正リクエスト拒否、配置・奪取・スコア、正常終了、BOOK 閉じ・投了など）。Wire ログは **§18 と同形式**（AI 着手は `solo_ai_turn` で識別）。
- **非スコープ**: 高度 AI、ログの別ファイル化、**2 PC 本番検証の代替**（最終的には実 2 人も別途推奨）。

### 18. 対戦系通信 Wire ログ・ソロ仮想接続検証（懸賞クローズ）

**結論（懸賞の扱い）**: サーバログ・F8 ログの双方で **NUI → client（Lua）→ server → client → NUI** の順が追え、ソロ検証で **マッチ通知と切断終了**まで一貫して問題なかった。**通信経路に異常は見えず、当該の検証・懸賞はここで終了**とする。

#### 背景

- 動作確認のデバッグログだけでは **往復の有無**が見えにくい。
- **2人接続**は環境の制約で常に使えるとは限らない（§15 にマルチクライアント検証の予定あり）。

#### 実装概要（コード側の整理）

| 区分 | 内容 |
|------|------|
| 設定 | `config.lua` の `Config.BattleWireLog`（`nil` のとき **`Config.Debug` に追随**）。本番は `false` 推奨。 |
| 共有 | `shared/battle_wire_log.lua` — `TcgBattleWireLogEnabled()` |
| サーバ | `server/battle_lobby.lua` / `server/battle_debug.lua` — 対戦系イベントの **受信**と **`TriggerClientEvent` 直前**に `[jp-tcgbook][wire]` を `print` |
| クライアント | `client/nui_callbacks.lua` — 対戦系 `RegisterNUICallback` → `TriggerServerEvent` 直前。`closeBook` 経由の `battleVirtualLeave` もログ。`client/main.lua` の `sendBattleNui` で対戦系 `SendNUIMessage` をログ |
| NUI | `server/main.lua` の `openBook` 応答 `data.ui.wire_log` が true のとき、`html/js/nui.js` で **fetch 送信**と **message 受信**を `console.log`。Citizen の F8 はオブジェクトを `[object Object]` に潰すため、**`tcgWireJson()`（`JSON.stringify`、長い場合は約2400文字で切り詰め）**で1行にまとめる |
| ソロ仮想接続 | `jp-tcgbook:server:battleSoloVirtualWireTest`（**`Config.DebugCommands` のみ**）。`soloVirtualLobby[src]` で「2人目なしの仮想接続中」を記録。切断は `battleVirtualLeave` で `virtualBattleEnded`（`reason=solo_wire_test`）。CPU デバッグ開始はソロ中は拒否。対戦タブに **「1人で仮想接続の往復を試す」**（デバッグ UI 表示時のみ）。`mock_data.js` に同等の擬似動作 |

#### 確認済みログの流れ（記録用）

1. **ソロ開始 → サーバ**: `server recv battleSoloVirtualWireTest` → `(solo) no second client...` → `server->client virtualBattleMatched ... solo_wire_test=true`
2. **切断 → サーバ**: `server recv battleVirtualLeave` → `server->client virtualBattleEnded ... reason=solo_wire_test`
3. **F8（NUI）**: `NUI fetch -> battleSoloVirtualWireTest {}` → `NUI->server battleSoloVirtualWireTest` → `client->NUI virtualBattleMatched ...` → `NUI message <- virtualBattleMatched {JSON}` → 切断時は `battleVirtualLeave` 系で対称

#### メモ

- **本物の2クライアント**での仮想ロビー（待受 ON → 相手サーバー ID で呼び出し）は、従来どおり **実機が揃ったときの検証**に回す。
- Wire ログは **負荷と情報量**があるため、本番では `Config.BattleWireLog = false` か `Config.Debug = false` を推奨。
