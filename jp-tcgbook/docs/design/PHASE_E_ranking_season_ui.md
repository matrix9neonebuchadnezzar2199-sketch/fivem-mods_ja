# PHASE E — ランキング（シーズン）・段位表示・レベル／連勝・対戦履歴（全体設計）

**対象リソース**: `jp-tcgbook`  
**前提**: PHASE 2c（`tcg_players.rating`・戦績）、PHASE 2d（敗北コピー）、`BattlePvp.Finish` → `RecordFinish` → `GrantOnFinish` の順が確立済み。  
**関連**: 日次集計は **PHASE C**（`tcg_daily_counters`）。本 PHASE は **試合履歴・ランキング UI・段位／EXP** を主担当。  
**文字コード**: UTF-8（BOM なし）

---

## 1. 目的・スコープ

### 1.1 目的

- **ランキングタブ**: シーズン見出し・リーダーボード・自分の順位／段位／レベル／連勝を一覧で提示する。
- **対戦履歴タブ**: 「誰と・いつ・勝敗・レート変化」などを **試合単位**で追えるようにする（監査・プレイヤー満足・将来のシーズン集計の材料）。
- **段位（ランク呼称）**: `rating`（Elo）から導出する **ギルド風徽章ランク**を UI で表示する。
- **レベル／EXP／連勝**: モチベ用。**勝利ベース EXP**・**連勝ボーナス**を採用。

### 1.2 スコープ内

| 領域 | 内容 |
|------|------|
| **シーズン概念** | **通年モード**（表示: 「シーズン：通年開催」）を第一実装。番号シーズン・締め処理は後続（§8）。 |
| **データ** | `tcg_match_history`（仮称）の新設と Finish 時 INSERT、参照 API |
| **プレイヤー拡張** | `exp` / `level` / `win_streak_current`（列名は実装時に確定）など |
| **NUI** | **ランキング**タブ・**対戦履歴**タブ |
| **段位表** | 確定呼称一覧（§4）は `locales` または config |

### 1.3 スコープ外（本 PHASE の初期スパンではやらない）

- 全着手ログ・盤面フルスナップショットの保存
- IP・ハードウェア ID の収集
- マッチメイキング用の隠し MMR（当面は **`rating` のみ**）
- デッキ内容の履歴保存（`deck_id` / フィンガープリントは将来オプション）

---

## 2. 用語整理

| 用語 | 意味 |
|------|------|
| **ランキング（タブ）** | UI。リーダーボード＋自分のサマリを載せる画面全体 |
| **シーズン** | 集計・表示の枠。初期は **`evergreen`（通年）** のみ運用してよい |
| **段位／ランク** | **G〜SS** のレターと **徽章名**の組（表示は §4）。**`rating` の閾値**で決定（config） |
| **レベル** | **EXP** の累積で上がる **プレイヤーLv**。`rating` とは独立 |
| **連勝** | リアル PvP **`reason=normal` の勝利**が続くカウント。投了・切断でリセット |

---

## 3. シーズン方針

### 3.1 通年（既定）

- **表示ラベル**: **「シーズン：通年開催」**（文言は `locales` で調整可）
- **内部 ID**: 例 `season_id = 0` または `evergreen`
- **リーダーボード**: 当面 **`tcg_players.rating` DESC**（オールタイムと同一）

### 3.2 番号シーズン（後続）

- テーブル `tcg_seasons`（`id`, `name`, `starts_at`, `ends_at`）等を追加し、**締め時にソフトリセット**（段位・レートの扱いは運営設定）
- **match_history** に `season_id` を付与すると「そのシーズンのみ」集計が容易

## 4. 段位（ランク呼称）— 確定

**形式**: **`{レター}：{徽章フレーズ}`**（素材語は **英単語**、漢字の銀・金等は使わない）。

| `rank_order` | `rank_code` | 表示文字列 |
|--------------|-------------|------------|
| 1 | `g` | G：Woodの徽章 |
| 2 | `f` | F：Bronzeの徽章 |
| 3 | `e` | E：Ironの徽章 |
| 4 | `d` | D：Silverの徽章 |
| 5 | `c` | C：Goldの徽章 |
| 6 | `b` | B：Platinumの徽章 |
| 7 | `a` | A：Astralの徽章 |
| 8 | `s` | S：Dragonの徽章 |
| 9 | `ss` | SS：Mythologyの徽章 |

- **`rating` 閾値**（各区間 `[min, max)`）は **`config.lua`** に日本語コメント付きで定義。初期は均等分割でも、上位だけ幅を広げてもよい。
- **ダミー／デバッグ用 citizenid** を leaderboard から除外するかは **config フラグ**で任意（dryrun 用 dummy 想定）。

詳細メモのコピー: `docs/design/RANKING_SEASON_LEVEL_HISTORY.md`（§3 同期維持）。

### 4.1 徽章画像アセット（NUI）

- **配置**: `html/assets/ranc/`（フォルダ名 **ranc** で固定）
- **マニフェスト**: `fxmanifest.lua` の `files` に **`html/assets/ranc/**/*.png`** を含める（含めないと `cfx-nui` 経由で読めず真っ黒になる）
- **NUI URL**: 既存カード・`duel_back` と同様 **`https://cfx-nui-<resource名>/html/assets/ranc/<ファイル>`** を組み立てる

| `rank_code` | ファイル（現状） |
|-------------|-------------------|
| `g` | `Wood.png` |
| `f` | `Bronze.png` |
| `e` | `Iron.png` |
| `d` | `Silver.png` |
| `c` | `Gold.png` |
| `b` | `Platinum.png` |
| `a` | `Astral.png` |
| `s` | `Dragon.png` |
| `ss` | `Mythology.png` |

- **フォールバック**: `img.onerror` またはプレースホルダー画像で欠損・改名に耐える（運営がファイルを差し替えたときの事故防止）

## 5. レベル・EXP・連勝

### 5.1 EXP

- **主因**: リアル PvP **勝利**ごとに基礎 EXP（`Config`）
- **敗北**: 既定 **0**（運営が付与したければ config）
- **引き分け**: 中間値または 0（config）

### 5.2 連勝ボーナス

- **採用**。初版は **EXP に倍率または加算**を掛ける形が実装しやすい（段階式・上限あり・`config` 化）。
- **リセット条件**: `reason ~= 'normal'` の終了、または **敗北**で **0** に戻す（仕様は実装時に `BattleStats` 側で一本化）

### 5.3 レベル曲線

- 累積 EXP → レベルは **テーブル or 式** を `config.lua` に記載

---

## 6. 対戦履歴（データ）

### 6.1 保存する項目（合意）

**試合 1 行**に最低限:

- `match_id`（UUID または `session_id`）
- `finished_at`
- `is_real_pvp` / `reason`
- 両者 `citizenid`、**表示名スナップ**（任意だが UI に効く）
- `score_a` / `score_b`、**勝敗**（一方視点でよい＋導出可）
- **`rating_*_before` / `after`**（監査・表示用）
- **敗北コピー**: 成否、`card_id`（あれば）

**保存しない**: 全着手ログ、盤面全歴、IP・HW ID。

### 6.2 タイミング

- **`BattleStats.RecordFinish` 成功後**（または同一トランザクション相当の直後）に INSERT。`GrantOnFinish` 後に **コピー列だけ UPDATE** する二段でも可。

---

## 7. ランキングタブ（UI）

- **ヘッダ**: シーズン表示（通年／将来は期間付き）
- **自分**: 段位文字列・`rating`・**Lv / EXP**・**現在連勝**
- **一覧**: TOP N（50〜100）＋**自分の順位**（別 API で「自分 ±」でも可）
- **匿名**: `citizenid` の丸表示は避け、**ゲーム内名＋必要ならマスク ID**（既存日記の方針と整合）

## 8. 分割実装（サブ PHASE 案）

| ID | 内容 | 受け入れの目安 |
|----|------|----------------|
| **E1** | `tcg_match_history` + Finish 時書き込み + 自分用一覧 API | DB に行が溜まり、API が最新 N 件を返す |
| **E2** | NUI **対戦履歴**タブ | 実機で一覧表示 |
| **E3** | `exp` / `level` / `win_streak` + Finish 時更新 + **連勝 EXP ボーナス** | 勝敗で値が変わる |
| **E4** | NUI **ランキング**タブ（通年・`rating` 順・自分サマリ） | 文言「シーズン：通年開催」 |
| **E5** | **段位表示**（閾値 config + §4 文字列） | `rating` と表示ランクが一致 |
| **E6（任意）** | **番号シーズン**・締めジョブ・ソフト降下 | 運営がシーズンを切ったときのみ必須 |

**PHASE C**（日次カウンタ）は **E1 と並行可能**。履歴が無くても日次は動くが、**運営ダッシュボード**を見るなら履歴があると解析しやすい。

### 8.1 実装初期から入れておく推奨（おすすめ機能・エラー防止）

「後から足すと漏れやすい」ものを **E1〜E5 の受け入れに織り込む**想定で列挙する。

| 区分 | 内容 |
|------|------|
| **アセット配信** | 徽章 PNG を **`fxmanifest` `files`** に登録（§4.1）。デプロイ後に `/refresh` 忘れで詰まりがち |
| **履歴の一意性** | `match_id`（または `session_id`）に **UNIQUE**。`Finish` の異常二重呼び出し・リトライで **履歴が複製**されないようにする |
| **一覧クエリ** | リーダーボード・履歴は **`LIMIT` 上限**＋必要なら **ページング**。`rating` / `finished_at` 用 **INDEX** を `install.sql` で先に定義 |
| **権限** | 対戦履歴 API は **ログイン中の `citizenid` の行のみ**。他人の履歴を返さない（サーバーで必ずフィルタ） |
| **XSS** | 表示名スナップは NUI で **エスケープ**またはテキストバインドのみ |
| **段位フォールバック** | `rating` が閾値テーブルの隙間に落ちないよう **下限＝G** をコード側で保証（config ミス耐性） |
| **除外リスト** | dryrun 用 **`jp-tcgbook-debug-peer-dummy`** 等を **リーダーボードから除外**（`Config` 配列が扱いやすい） |
| **履歴 INSERT 失敗** | Elo 更新と履歴の **どちらを優先するか**を決め、失敗時は **`[wire]` または `print`** で検知可能に（サイレント欠損を避ける） |
| **機能フラグ** | `Config.EnableRankingUi` のような **タブ自体の ON/OFF**（未完成 UI を本番に出すミス防止） |
| **時刻表示** | プレイヤー向けは **JST 表記で統一**（UTC 保存でも UI でそろえる） |

## 9. 有名 TCG のランキング類型（設計の参考）

実装の丸コピーではなく **論点の借用**に留める。

- **階層ランク＋シーズンリセット**（MTG Arena 型）— 本 MOD では **段位表示＋将来シーズン**で近似
- **表示ランクと隠し MMR 分離**（Hearthstone 型）— 当面は **`rating` のみ**でよい
- **ポイントラダー＋上位で Elo**（Pokémon TCG Live 型）— 将来「シーズンポイント」列を足す余地
- **イベント別 DP／段位**（マスターデュエル・カップ型）— **別 `event_id`** で実装するのが安全
