## §21 NUI: コレクションタイルの固定サイズ・デッキ編成ボタン拡大

### 背景

- コレクションのサムネが **元画像の縦横比・内在的サイズ** の影響でグリッド上のカード枠の見た目がばらついていた。
- デッキ編成の **スロット削除（×）** と **所持カードの追加（+）** が小さく、視認性・押しやすさに課題があった。

### コレクション／デッキ（所持カードペイン）のタイル

**ファイル**: `html/css/collection.css` / `html/css/deck.css`

- グリッドに **`align-items: start`**（行の最大高に引き伸ばさない）。
- カード枠: **`width: 100%`**, **`min-width: 0`**, **`overflow: hidden`**。
- イラスト枠（`.card-art` / `.slot-art`）: **`flex: 1 1 0`**, **`min-height: 0`**, **`overflow: hidden`**（フレックス子の `min-height: auto` による伸長を抑止）。
- 画像: **`object-fit: cover`**, **`object-position: center`**, **`display: block`** 等で **固定枠内に収める**。
- コレクションの **`.card-name`**: デッキ同様 **2 行クランプ**（長い名前で枠高が不揃いになるのを防止）。

**コミット**: `0104b8a`（push 済み）

### デッキ編成: 削除ボタン・追加ボタン

**ファイル**: `html/css/deck.css`

- **`.slot-remove`**: `calc(12px * var(--book-fs-mul))` ＋ `min` 28px、× 文字拡大、枠 2px・影で視認性向上。`:active` で軽い縮小フィードバック。
- **`.add-btn`**: `calc(17px * var(--book-fs-mul))` ＋ `min` 44px、非ホバー時 `scale(0.72)`、**+** を `calc(24px * var(--book-fs-mul))`、ボーダー・グラデ強化。`:active` フィードバック。

**コミット**: `dcac05e`（push 済み）

## §22 デッキ編成：別カード化／画像欠け／名前が絵と不一致（再調査〜解消）

### 問題（実機）

- **所持カード**から **+** でマイデッキに追加すると、**別カードのように見える**・**画像が出ない**・**名前が古い（モンスター名のまま）** などの報告。
- コレクション側は画像が出るが **文言だけ絵と合わない**ケースもあり、運営が **画像だけ差し替え**した一方で **`shared/cards.lua` の `name` を更新していない**と説明がつく状態だった。

### 原因の整理

1. **表示データの参照元**  
   カード名・画像パス・説明の **正本は `shared/cards.lua` の `TcgCardsMaster`**。DB の `tcg_cards_master` は起動時 UPSERT で **Lua と同期する設計**だが、`Config.SeedCardsFromLua = false` のときは **既存行が自動では上書きされない**運用になりやすい。BOOK は **`openBook` で Lua マスタを NUI に渡す**ため、表示は **Lua 優先で整える**のが筋。
2. **デッキスロットの並び**  
   サーバーから返る `slots` が **配列順と `slot_index` が一致しない**と、クライアントで **スロットとカードの対応がずれる**。
3. **画像だけ差し替え**  
   `tcg_<card_id>.jpg` の **中身だけ差し替えても `name` は変わらない**。絵は旅する錬金術師なのに **`name` が「歩くキノコ」のまま**のような **見かけの不整合**が起きる。

### 対応（コード）

- **`server/database.lua`**  
  `GetDeckById` で JOIN した行を組み立てる際、**該当 `card_id` が Lua にあれば表示用フィールドを Lua で上書き**（DB が古くても BOOK の名前・パスを Lua に寄せる）。
- **`html/js/deck.js`**  
  **`normalizeDeckSlots`**（`slot_index` 1〜10 で正規化）、**`hydrateDeckCardDisplay`**（クライアントのマスタマップで表示寄せ）、**グリッド／統計／所持ペイン**で同じ経路を使うよう統一。
- **Git（例）**: `fa3ce09` — `fix(jp-tcgbook): deck slots align with Lua master for display`

### 対応（マスタ文案・画像整合）

- C ランクキャラ 4 枚（`tcg_c_slime` / `rat` / `mushroom` / `ghost_jelly`）は **差し替え後のイラスト**に合わせて **`name` / `name_en` / `description` / `description_en` を改名**（例: 緋衣の吟遊詩人、紺鉄の若侍、翠瓶の錬金術師、碧珀の獅子騎士）。
- **`docs/design/CARD_MASTER_NAMING_AND_I18N.md`** の対応表も同期。
- **Git（例）**: `133542d` — `feat(jp-tcgbook): rename C-rank character cards to match new art`

### 運用メモ（再起動・DB）

- **RESOURCE 再起動だけ**でも NUI は **Lua の最新マスタ**を読むため、**名前の修正はその時点で反映**されやすい。
- **MySQL 上の `tcg_cards_master` まで完全一致**させたいときは **`Config.SeedCardsFromLua = true` で再起動 → 検証後 `false`**（手順の詳細は **README「カードマスタと DB」**）。

### 判定

- **画像との整合**: OK（マスタ改名により **名前・説明も絵と一致**）。
- **デッキ編成の取り違え**: 上記コードパスで **再現しにくい**状態まで是正。

## §23 対戦タブ：フリーバトル（CPU 練習）復活・疑似通信 UI の整理

### 背景

- **対戦**タブで **フリーバトル（練習）** が見えなくなっていた。原因は、CPU 開始／着手が **`Config.DebugCommands` に依存してサーバー拒否**され、かつ NUI 側も **デバッグロビー表示時だけ** CPU ボタンが出る構成だったため（本番 `DebugCommands=false` だと **練習導線が消失**）。
- **疑似通信**（1 人で仮想接続の往復を試す）は **非表示のまま**とする依頼あり。

### 対応

1. **`server/battle_debug.lua`**  
   - **`battleDebugStartCpu`** / **`battleDebugPlace`** から **`Config.DebugCommands` ガードを削除**（CPU 練習は常時可）。  
   - **`battleDebugLookupId`**（サーバー ID 検索・応答のみ検証）は **従来どおり DebugCommands 必須**。  
   - ファイル先頭コメントを「CPU 練習 + 検索だけデバッグ」に合わせて更新。
2. **`html/js/battle.js`**  
   - 使用デッキ直下に **`renderPracticeCpuSection`**（**フリーバトル（練習）**・**CPU と対戦する**）。10 枚未満／仮想対戦接続中／ソロ検証接続中は開始不可（ヒント表示）。  
   - **デバッグ用ロビー**展開時は **CPU ボタンを削除**（練習はフリーバトルに一本化）。**疑似 PvP ソロ**ボタンは従来どおりデバッグ時のみ。  
   - 仮想対戦ブロックにあった **「1人で仮想接続の往復を試す」** 行を **削除**（疑似通信 UI を出さない）。
3. **文言・エラー**  
   - **`html/js/i18n.js`** … 練習用見出し・フッター説明・終了確認など JA/EN。**`battle_debug_lobby_hint`** から CPU 開始の記述を整理。  
   - **`server/battle_lobby.lua`** / **`server/battle_pvp.lua`** / **`html/js/mock_data.js`** … 「デバッグ対戦」系を **「CPU対戦（練習）」** に寄せて統一。
4. **Git（push 済み）**: `a39931e` — `fix(jp-tcgbook): restore free CPU practice battle on Battle tab`

### 運用メモ

- CPU 練習は **ランキング・履歴・経済の対象外**（従来どおり `battle_debug` 経路）。  
- **疑似 PvP ソロ**は引き続き **`Config.DebugCommands=true` のときのみ**（設計どおり）。
