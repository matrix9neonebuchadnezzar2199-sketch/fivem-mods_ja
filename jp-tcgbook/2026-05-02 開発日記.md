## 確認メモ — 「ランキング」機能（設計着手前の論点）

運営・開発で一度すり合わせしてから DB・API・NUI に落とす。**有名 TCG は参考までに**（仕様の丸コピーではなく、RP サーバーに合う要素だけ抽出する）。

### UI のイメージ候補

- **BOOK 内 dedicated タブ**「ランキング」: 一覧 + 自分の位置（固定ヘッダまたはサイド）
- **表示形式**: 全域 TOP N（50〜100）、**自分 ±10 位**だけ表示（大手モバイル TCG でよくある省データ手法）
- **シーズン**: 「オールタイム」と「今シーズン」の切り替えタブがあるとリセットでも盛り上がりやすい
- **匿名性**: `citizenid` の丸表示は避け、**ゲーム内名 + server 固有の短い表示 ID** やマスク済み ID の運用を検討

### 管理・表示できるとよい情報（データ設計の素材）

- **必須寄り**: `rating`（Elo）、`wins` / `losses` / `draws`（既に `tcg_players` にあり）、試合数の派生値（勝率などは計算で可）
- **あると便利**: 最終対戦日時、シーズン開始からの試合数、（将来）デッキタイプ別・レーン別はスコープ過大になりがちなので後回しでよい
- **盛り上げ用（任意）**: **段位・バッジ・プロフィール用タイトル**（例: 「連勝 5」のような実績解除）は、`tcg_players` だけでなく **別テーブル or JSON** で持つと伸びやすい

### 有名 TCG・サービスから拾えるヒント（調査の着手点）

- **MTG Arena**: Constructed の階層レッド・マイルストーン報酬 → 「到達型」の目標が明確
- **Hearthstone**: レジェンド帯・月度リセット → **シーズン**と高位の稀少感
- **ポケポケ / Pokémon TCG Live**: ランクマの段階・イベント別報酬 → **期間限定イベント**との組み合わせ（運営カレンダーと連動）
- **遊戯王マスターデュエル**: ランクと勝敗報酬の分離 → **ランキング表示と報酬経済は別設計**にすると調整しやすい

### 決めておくと実装が楽になること

- **ランキング対象**: リアル PvP のみ（2c のポリシーと一致）か、solo を別ランキングに含めるか（通常は **除外**）
- **更新タイミング**: 試合終了時に即反映でよいか、バッチ集計が必要か（現状は **即反映で十分**）
- **表示のデータソース**: `tcg_players` のみで足りるか、TOP100 用にキャッシュテーブルが要るか（人数規模が小さいうちは **`ORDER BY rating LIMIT`** で十分なことが多い）
