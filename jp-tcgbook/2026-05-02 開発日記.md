## PHASE 2d・実機検証

- **実装**: 敗北時カード1枚コピー（`initial_hands`・`winner_reward_pool`・`BattleRewards.GrantOnFinish`・`Database.AddCardToPlayer`）。設計は `docs/design/PHASE_2d_defeat_reward.md`。コードは **`cacda3d`** を参照（以降のコミットがあれば `git log` で追う）。

### 実機結果（2026-05-02・PvP solo・2d 実装後リグレ）

**環境**: `ensure jp-tcgbook` 後、PvP solo 1 局 normal 完走（Wire ON）。

**セッション例**: `pvp_solo_1777715512_5`（終了時刻目安 **18:52:07**）。

**確認できたログ（要点）**:
```
[jp-tcgbook][wire][stats] skip non-real-pvp session=pvp_solo_1777715512_5
[jp-tcgbook][wire] BattlePvp.Finish session=pvp_solo_1777715512_5 reason=normal real_pvp=false
```

**読み取り**:
- **PHASE 2c**: solo で Stats がスキップされ、`real_pvp=false` で Finish している。**2d 実装後も経路は問題なし**。
- **PHASE 2d**: **`[jp-tcgbook][wire][rewards]` は一切出ないのが正しい**（`GrantOnFinish` は `is_real_pvp` が false なら即 return・ログも出さない設計）。solo で報酬が付くとバグ。

**任意（統合経路だけ）**: **リアル 2 クライアント**で招待～ normal 完走し、同じ Wire 行が本番 `session_id` で出ることを見たい場合のみ。

**1 人開発用（疑似ではなくフック直叩き）**: 仮想ロビーは **自分の server ID を相手に指定できない**ため、単一クライアントでは `BattlePvp.Start` ～完走の本番経路を再現できない。代わりに **`tcg_debug_finish_hooks_dryrun`**（`server/battle_finish_dryrun.lua`）で `RecordFinish` + `GrantOnFinish` だけを **実プレイヤー + DB 上のダミー相手** `jp-tcgbook-debug-peer-dummy` に対して実行し、tx コンソールで Wire / DB を見る。  
- 使い方: `tcg_debug_finish_hooks_dryrun lose 5`（src=5 が敗北→**コピーは自分**へ）／`win 5`（勝利→コピーはダミー行）。`Config.DebugCommands`、プレイヤー実行時は ACE `command.tcg_debug`。マスタ 0 件の環境ではプール組み立てに失敗する。

## M1/M2 実機検証・TX ログ提出（運用メモ）

### 実機テストは必要か

| 対象 | 実機の必要性 | 理由 |
|------|----------------|------|
| **M1 PHASE C（日次）** | **必須ではない**がログ確認は推奨 | **`tcg_debug_finish_hooks_dryrun`** が `RecordFinish` / `GrantOnFinish` を通すため、**1 台・TX ログ**で `[wire][stats] daily` と **`tcg_daily_counters`** を見れば十分なことが多い |
| **M2 PHASE E1（対戦履歴）** | **`tcg_match_history` を確認するなら実質必要** | 履歴 INSERT は **`BattlePvp.Finish` 内のみ**。dryrun は Finish を呼ばないため **履歴行は増えない**。本番経路の実証には **リアル PvP を 1 局 normal 完走**するか、将来 Finish 経由のデバッグを足すまで **実機相当のテストが必要** |

**まとめ**: 日次だけ見るなら dryrun + TX でよい。**履歴テーブルまで含めて確証を取るなら、実機でリアル PvP 完走（または 2 台）を一度やるのが確実**。

### 実行後に TX ログを提出する手順（提案）

1. **`refresh` / `ensure jp-tcgbook`**（`install.sql` で `tcg_daily_counters` / `tcg_match_history` が作成されること）
2. **`Config.BattleWireLog = true`**（または `Config.Debug = true` で Wire 追随）
3. **M1 確認**: `tcg_debug_finish_hooks_dryrun lose <server_id>` を 1 回 → `[jp-tcgbook][wire][stats] daily` … と **`tcg_daily_counters`** の行
4. **M2 確認**: **リアル PvP** を **normal 完走** → `[jp-tcgbook][wire][match_history] insert ok …` と **`tcg_match_history`** の 1 行（併せて `elo` / `winloss` / `rewards` があればよい）
5. **txAdmin のサーバーログ**から該当時間帯をコピーして提出（F8 不要）

**記録方針**: 開発者側でログファイルを保持する代わりに、**実行後に TX ログをチャット等へ貼ってもらえればレビュー可能**とする。

### 実機ログ記録（2026-05-02）

**TX（サーバー）**

- **`ensure jp-tcgbook`**: `[tcg] テーブル作成完了`。**`playerskins` 不存在**は `qbx_core` / `illenium-appearance` の別問題（jp-tcgbook 無関係・振り返り表どおり無視でよい）。
- **PvP solo 完走**（例: `pvp_solo_1777723554_7`）: `[wire][stats] skip non-real-pvp` → `BattlePvp.Finish … real_pvp=false`。想定どおり（日次・履歴・Elo 対象外）。
- **dryrun `lose <server_id>`**（例: `pvp_debug_dryrun_1777723606`）: `elo` / `winloss` / **`[wire][stats] daily … ok=true`** / `rewards grant … ok=true`。**M1（PHASE C）実機確認として問題なし**。**`[match_history]` は出ない**（dryrun は `Finish` 非経路のため仕様どおり）。

**F8（クライアント・NUI Wire）**

- **PvP solo**（例: `pvp_solo_1777723695_7`）: `battlePvpStartSolo` → `battlePvpStarted` → 複数 `battlePvpPlace` / `battlePvpState`（`turn_no` 整合・`flipped_cells` あり）→ **`battlePvpEnded` `reason=normal`**（例: スコア 3 vs 7・`outcome=lose`）→ `closeBook` / `battleVirtualLeave`。**UI〜終了オーバーレイまで矛盾なし**。
- Stats／日次／履歴の可否は **サーバー tx ログ**側の判定（F8 には出ない）。

**未ログ（次の確認）**: **リアル PvP 完走**時の **`[jp-tcgbook][wire][match_history] insert ok`** と **`tcg_match_history` 1 行**（M2 の残り）。

## 開発方針の記録（1人開発・疑似PvPソロ）

**前提**: jp-tcgbook は **基本 1人で開発**する。2クライアント常設を前提にしない。
