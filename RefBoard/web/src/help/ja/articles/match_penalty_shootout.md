# PK 戦を進める

## このページでわかること

- 延長後の PK 戦への遷移手順
- `PenaltyShootoutPanel` の使い方（成功 / 失敗の記録）
- 勝敗確定の自動判定と試合終了までの流れ

## 前提条件

- 対象の試合が **編集モード**で開かれている。
- 通常の前半・後半・（必要なら延長）が **終了**しており、**スコアが同点**であること。
- PK に進むことについて両チームで合意済み（運用ルール）。

## 手順 — PK 戦の開始

1. `MatchStatusCard` の **ハーフ切替**から「PK」を選ぶ。
2. 確認ダイアログで「**PK 戦を開始しますか？**」と表示されるので、**先攻チーム**を選んでから確定。
3. `current_half` が **`pk`** に切り替わり、画面に **`PenaltyShootoutPanel`** が表示されます。
4. スコアの内訳（`breakdown`）に `pk` カラムが追加され、`MatchStatusCard` で「前半 / 後半 / 延長 / PK」の内訳が並びます。

## 手順 — 1 本ずつ記録する

1. パネル上で **キッカー**を選択（出場選手から。退場済み・既に PK 失敗・成功済みの選手も再選択可能 — 運用次第）。
2. **成功（決めた）** または **失敗（外した／止められた）** を押す。
3. 内部的には `refboard:event:record_penalty` が走り、成功の場合のみ `penalty_success` イベントとして記録されます（`pk` 内訳のスコアが +1）。
4. 先攻 → 後攻 → 先攻 → … と **交互に**記録します。順序はパネル UI が誘導します。

## 勝敗の自動判定

- サーバー側 `evaluatePenaltyShootout` が **5 本ずつのサドンデス前後**で勝敗判定を行います。
  - 5 本終了時点で差がつけばその時点で勝者確定。
  - 5 本ずつで同点 → 6 本目以降は **1 本ごとに同数で差がつけば即終了**（サドンデス）。
- 勝敗が確定すると `refboard:event:pk_decided` がブロードキャストされ、**`PenaltyShootoutPanel` に勝者が表示**されます。

## 試合終了

1. 勝者が表示されたら、パネル下の **「試合を終了」** から確認ダイアログへ。
2. 確定すると通常の試合終了フロー（`Match.finish`）が走り、`status` が `finished` になります。
3. 本戦スコアは **同点のまま記録**され、PK の勝敗は `pk` 内訳と勝者情報で表現されます（PK 勝ちでも本戦スコアは書き換えません）。

## やった後どうなる？

- データ管理 → 試合履歴の **PK 列**にスコアが入ります（例: `2-2 (PK 4-3)` のような表示は UI 側で組み立て）。
- 選手統計の `penalty_success` が +1 されます（成功した選手のみ）。
- 取り消しはイベントタイムラインの該当 PK 行から個別に「取り消し」可能。本戦スコアには影響しません。

## 間違えた場合

- **キッカーを間違えた**: 該当 PK イベントを取り消し → 正しいキッカーで記録し直し。
- **先攻チームを間違えた**: PK 戦そのものをキャンセルする UI は **未実装**です。サーバー管理者に依頼するか、運用上「事実は逆だった」と注記して進めてください（`docs/sprints/sprint_07_uiux_findings.md` で議題化候補）。
- **PK に入る前に戻したい**: 試合を **再編集**で開き直し、`current_half` を延長または後半に戻す UI は現状ありません。**PK 開始前**に十分確認してください。

## よくある質問

**Q. 5 本ぴったりで終わらなかった場合の表示は？**  
A. パネルは自動でサドンデスモードに切り替わります。両チームが同数蹴った時点で差を判定するロジックなので、片側だけ多く蹴ることはありません。

**Q. PK スコアだけ手動で直したい。**  
A. PK 内訳の手動編集 UI は **未実装**です。スコア手動編集（`match_manual_score_edit`）は **本戦スコア専用**で、`pk` 内訳は対象外。
