# 接続が切れた、データは大丈夫？

**結論**: RefBoard は **サーバー上の MySQL を正** とする設計なので、**サーバーに届いた操作は保存**されます。クライアントは表示と入力役です。

## なぜ大丈夫か

- 編集操作は NetEvent でサーバーに送られ、成功時に DB が更新されます。  
- **オートセーブ**（`match_drafts`）は編集中の UI 状態のバックアップ用途です。  
- 切断しても、**最後にサーバーが受理した時点**までの試合データは DB に残ります。

## 切断のパターン

### 自分の FiveM が落ちた

- ロックはタイムアウトで **自動解放** されます。  
- 再接続後、試合一覧から同じ試合を開き、必要ならロックを取り直してください。

### 一時的なネットワーク不安

- 一部の操作でトーストに失敗が出ることがあります。落ち着いて **同じ操作を再度** 試してください。  
- NUI のデバッグが必要なときは `localStorage.refboard_trace = '1'` を設定してリロードし、F8 コンソールを確認してください（`docs/sprints/sprint_06_pretriage.md` 参照）。

### サーバーまたは DB ダウン

- **ヘルスチェック** で接続・スキーマを確認してください。復旧後、再度操作します。

## 復旧の手順

1. 再接続する  
2. 試合一覧から該当試合を開く  
3. 必要なら **編集ロック** を取り直す  
4. 不安なら **ヘルスチェック** を実行する  

## やった後どうなる？

- 正常復旧: 切断前に **保存済み** のデータはそのまま見えます。  
- 未送信の操作: クライアント側だけにあった入力は **失われる** ことがあります。重要操作のあとは保存成功表示を確認してください。

## よくある質問

**Q: オートセーブの「✓」が出る前に落ちたら？**  
A: その操作はサーバーに届いていない可能性があります。再度同じ操作を行ってください。
