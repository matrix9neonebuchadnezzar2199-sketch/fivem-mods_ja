# 削除しようとした選手にイベント履歴がある（E3006）

## 何が起きているか

試合の登録メンバーから選手を削除しようとしたところ、**`E3006`（`player_has_events`）** が返ってきました。これは **その選手がタイムライン上のイベントに紐づいている**ためです。

具体的には、削除対象の選手が以下のいずれかとして **無効化（取消）されていない `match_events`** に登場している場合に発生します。

- 得点者（`player_id`）
- アシスト（`assist_player_id`）
- 交代 IN（`sub_in_player_id`）
- 交代 OUT（`sub_out_player_id`）
- イエロー／レッドカードの対象（`player_id`）

データの整合性を守るための仕様です。**「ゴールしたのに登録から消える」状態を作らない**ための保険、と理解してください。

## 前提条件

- 試合のステータスが **`draft`（下書き／進行中）** であること。終了済みの試合では選手削除そのものが拒否されます（**`E3004`（`bad_status`）** — `shared/error_codes.lua` の `MATCH_ALREADY_FINISHED` に対応）。
- 削除したい選手が **タイムラインに登場していない**こと（本記事のテーマ）。

## どう解決するか

### 方法1: 該当イベントを先に取り消す（推奨）

タイムライン（試合経過タブ）から、その選手に紐づくゴール・アシスト・交代・カードを **「取消」** で順に無効化（`voided_at` を立てる）してください。すべて取り消した後で、もう一度メンバー表の **削除** を実行すれば成功します。

1. 試合詳細 →「試合経過」タブを開く  
2. 対象選手の名前が出ているイベント行を探す  
3. 行のメニューから **取消** を選ぶ  
4. すべて取り消し終わったら、メンバー表の **削除** を再実行  

### 方法2: 選手を入れ替える（別人として続ける）

途中から「実は別人だった」「途中交代の登録ミスに気付いた」のような状況なら、削除ではなく **正しい選手を追加してから交代イベントで入れ替える**ほうが履歴的に自然です。誤登録の選手がプレーしていない時間帯のイベントしか持っていないなら、方法1で取り消したうえで削除→新規追加でも構いません。

### 方法3: バックアップからの復元（最終手段）

UI 上の取消では難しい大量修正が必要な場合は、**データ**画面の **JSON バックアップ**から該当時点に戻す運用を検討してください。

## やった後どうなる？

- 方法1で取消が完了すると、メンバー表の削除が通り、**ローカルデータから当該メンバーが外れます**。
- 方法2ではメンバー表に**両方の選手が残る**形になります（正史として）。
- 方法3はバックアップ運用の範囲です。直前のエクスポートを取る習慣を推奨します。

**できないこと**: タイムラインに登場している選手を、イベント側を残したまま削除する（仕様上不可）。

## よくある質問

**Q. なぜ「取消」したイベントは `E3006` の対象にならないの？**  
A. 判定は **取り消されていないイベント**だけを数えます。一度取り消したイベントはカウントから外れます。

**Q. 終了済みの試合でメンバーから消したい**  
A. 終了済み試合では削除そのものが **`E3004`（`bad_status`）** で拒否されます。**再編集（reopen）** で `draft` に戻してから方法1を試してください。

**Q. 「取消」もしたくないし削除もできない、何のために削除があるの？**  
A. 削除は **誤って追加した直後の取り消し** を主眼に置いた機能です。プレー実績がついた選手は履歴として残す前提なので、`E3006` が出た時点で「もう履歴の選手」と考えるのが運用上は正解です。

## それでも解決しない場合

- タイムラインを上から順に確認し、対象選手名が残る行がないか再チェックする。  
- **データ**→**全データのバックアップ (JSON)** で現状を保存してから、ブラウザを再起動してやり直す。
