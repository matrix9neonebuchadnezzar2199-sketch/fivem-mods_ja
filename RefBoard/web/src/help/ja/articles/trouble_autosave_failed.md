# オートセーブが失敗した時

オートセーブ表示が **エラー** になったり、サーバー ACK に `error: 'tx_failed'` / **`E4003`** が含まれる場合の扱いです（スコア本体のトランザクション失敗でも同コードになることがあります）。

## 何が起きているか

直近の **DB 書き込み**（ドラフト保存やスコア更新など）が失敗しました。原因の例:

- MySQL 接続の一時障害  
- デッドロックやタイムアウト  
- バリデーション／整合性エラー  

## どう解決するか

### ステップ1: 再試行

画面上に **再試行** ボタンがある場合は押します。無い場合は、**同じ操作をもう一度** 試してください。

### ステップ2: 少し待ってから再実行

連続して失敗する場合は **数秒〜数十秒空けて** から再度試します。

### ステップ3: ヘルスチェック

**設定 → ヘルスチェック** で DB 接続・スキーマを確認します。

### ステップ4: ログ

サーバー管理者に **`Logger` の ERROR 行** と、可能なら **NUI トレース**（`refboard_trace`）を共有します。

## やった後どうなる？

- **成功**: インジケータが保存済み表示に戻ります。  
- **失敗が続く**: その時点の操作は **未保存のまま** になっている可能性があります。無理に進めず、ヘルスチェックとログ確認を優先してください。

## よくある質問

**Q: 画面上だけスコアが変わっているように見える**  
A: クライアントの先行表示の可能性があります。再読込でサーバー真値を確認してください。

**Q: `tx_failed` と `db_query_failed` の違い**  
A: 実装上の分類です。いずれも **DB 層の失敗** としてヘルスチェックとログから切り分けます。
