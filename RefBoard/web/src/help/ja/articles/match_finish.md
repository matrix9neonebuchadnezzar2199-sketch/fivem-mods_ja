# 試合を終了する／再編集する

## このページでわかること

- 試合を `finished` 状態に確定する手順
- 終了後にデータ／UI がどう変わるか
- **再編集（reopen）** で試合を開け直す手順と注意点

## 前提条件

- 対象の試合が **編集モード**で開かれている。
- 試合のハーフが **後半終了**（または PK 戦の決着）まで進んでいる。前半中の終了は確認ダイアログで止められませんが、運用上は推奨しません。

## 手順 — 試合を終了する

1. `MatchStatusCard` または画面ヘッダから **「試合を終了」** を押す。
2. 確認ダイアログで現在のスコアと内訳（前半 / 後半 / 延長 / PK）が表示されます。
3. **「終了として確定」** で `Match.finish` がサーバー側で実行されます。
4. `refboard:match:finished` がブロードキャストされ、全審判の画面が **閲覧モード**に切り替わります。

## やった後どうなる？

- `matches.status` が **`finished`**、`finished_at` が現在時刻で記録されます。
- スコアボード上に **「試合終了」** バッジ。
- イベントタイムライン・選手一覧は **読み取り専用**になります。
- データ管理 → 試合履歴に **確定スコアで載る**（reopen するまで）。
- `editor_locks` は自動解放されます（編集者がいなくなる）。
- オートセーブの草稿（`match_drafts`）は **保持**されます（再編集時にそのまま復元される）。

## 手順 — 再編集（reopen）

確定後に修正が必要になった場合の **緊急ハッチ**です。

1. 試合一覧（`MatchList`）で対象の試合行に表示されている **`[再編集]`** ボタンを押す。
2. 確認ダイアログで「**再編集すると試合は `in_progress` 状態に戻ります**」と確認。
3. 確定すると `Match.reopen` がサーバー側で走り、`reopened_at` / `reopened_by` が記録されます。
4. 編集ロックの取得を求められるので、通常の編集と同じく `session.enterEdit` で開きます。

## 再編集で **やってよいこと**

- ゴール・カード・交代の取り消し / 追記。
- スコアの手動編集（[手動編集](#/workspace/help/article/match_manual_score_edit)）。
- 選手追加・出場時間の修正。

## 再編集で **注意すべきこと**

- データ管理 → 試合履歴に表示される **確定スコアが書き換わります**。CSV エクスポート済みのデータとはズレるので、**取り回し中の集計を再生成**してください。
- `reopened_*` は `edit_logs` にも残るため、**再編集の事実は監査可能**です。「なぜ開け直したか」をイベントタイムラインのコメント等で残しておくと運用が楽です。
- **PK 戦の結果は再編集中にイベント取消で動かせる**ため、運用上は「PK の勝者が変わるレベルの再編集は原則しない」ルールを推奨します。

## 試合をキャンセル / 削除したい

- **キャンセル専用フロー**は現状ありません。試合を作ってしまった後に「やっぱり実施しない」ことになった場合は、終了せずに放置するか、サーバー管理者に DB 削除を依頼してください（運用ルールで決めるべき項目です）。

## よくある質問

**Q. 終了した試合のロックが残っていて開けない。**  
A. ローカル版では **編集ロックやサーバー接続はありません**。画面を再読み込みするか、試合一覧から当該試合を開き直してください。

**Q. 何度でも reopen できますか？**  
A. 仕様上は **何度でも可能**です。ただし `reopened_*` カラムは **最後の reopen 時刻 / 実行者**で上書きされるため、複数回の経緯は `edit_logs` 側で追ってください。

**Q. PK 戦の途中で「試合を終了」を押してしまったら？**  
A. 再編集で開け直し、PK イベントを最後まで記録するか、手動編集で内訳を整えてください。**ただし PK 戦の決着順序は手動編集では再現できない**ため、できるだけ PK 中は途中終了しないでください。
