# v0.9.0 / v1.0.0 リリーステスト計画（RefBoard）

実施日: _____________ 実施者: _____________ 環境: _____________

> 自動テストは v1.x 以降の検討とし、本計画は**手動**の受け入れ確認を前提とする。  
> FiveM 実機が無い場合は、該当シナリオを「未実施（理由: …）」と明記し、モック（`npm run dev`）で代替できる項目に分ける。

**v0.9.0 での刷新**: 既存のシナリオ 1〜7 は v0.9.0 想定で書かれているが、**v0.5.0 当時の前提**で止まっていた箇所に、v0.6〜v0.8 で追加された機能（ヘルプ、コンテキスト `?`、編集ロック奪い返し、DB 自動初期化、デモシード自動投入、フォント倍率切替、E3006、マーキー、小窓モード）を追補した。実機テストの主作業は本計画に沿った総点検である。

## 環境準備

- [ ] FiveM サーバー（テスト環境）
- [ ] MySQL 8.x または MariaDB 10.x
- [ ] 2〜3 台の FiveM クライアント（複数審判テスト用）
- [ ] `RefBoard` を `ensure`、審判 ACE `refboard.referee`
- [ ] DB: `install.sql` + 必要なマイグレーション（`migration_004` 等）
- [ ] `Config.SeedDemoTeamsOnStart = true` で起動し、5 チーム × 15 人が自動投入されることを確認（または false で手動 SQL 投入）
- [ ] `Config.AutoCreateSchema = true` で空 DB から `editor_locks` 作成が走ることを確認（既存 DB なら無関係）
- [ ] `Config.EnableTestCommands = true`（テスト時のみ）— `refboard_test_transaction` が使える状態
- [ ] DB バックアップを取得済み（テスト前 / テスト後の差分比較用）
- [ ] 各クライアントの `localStorage.refboard_settings` を一度クリア（v0.8.4 のフォント倍率・v0.6.x 以降の設定値が混ざらないよう）
- [ ] サーバーコンソールのログレベルを確認: `Config.LogLevel = 'DEBUG'` 推奨（テスト中のみ）
