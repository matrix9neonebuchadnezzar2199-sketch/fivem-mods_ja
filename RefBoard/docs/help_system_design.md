# RefBoard — アプリ内ヘルプ機能 設計書（v0.6.0〜）

**目的**: GitHub の README や `USER_GUIDE.md` だけでは「ツール使用中・困った瞬間」に参照されにくい。**アプリ内**で、**体系立てて学ぶ人**と**やりたいことから逆引きする人**の両方を満たす。

**ロードマップ上の位置**: **v0.6.0** で骨組み＋重要記事、**v0.7.0** で記事拡充・スクショ/GIF、**v0.8.0+** でコミュニティ拡張は任意。実機テスト前にヘルプを先に作る **B 案**（ヘルプ完成 → 実機テスト → v0.9 仕上げ）を採用する。執筆中に見つかった UI/UX 課題は `docs/sprints/sprint_07_uiux_findings.md` に集約し、v0.9.1 以降の改善ネタとする。

**関連**: エラー誘導は [error_handling.md](error_handling.md) の `code` と整合させる（例: 実装では `E1003` の `error` は `lock_held` — 記事 ID と文言をズラさないこと）。

---

## 1. 設計コンセプト

| 観点 | 方針 |
|------|------|
| 配置 | サイドバーに **「ヘルプ」** を追加し、`/workspace/help` などの **独立画面** |
| タブ | **タブ1: 項目ごと**（ツリー型・カテゴリから階層で到達） / **タブ2: やりたいこと**（動詞＋目的語の逆引き・検索） |
| 記事単位 | **Markdown 本文** ＋ **画像/GIF 埋め込み**（v0.7 で本番画質）＋ **「この機能を今すぐ実行」**（ルート遷移・必要ならダイアログ起動） |
| 横断 | 画面上部に **全文検索**（タブ横断。結果に所属タブのバッジ） |
| コンテキスト | 主要画面ヘッダに **`?`** → 現在画面に関連する記事だけを **スライドインパネル** で表示 |

**USER_GUIDE との関係**: 線形ドキュメントはリポジトリ用に維持。ヘルプは **タスク指向・エラー指向** を厚くし、重複は「概要は USER_GUIDE、手順の詳細と実行ボタンはヘルプ」で役割分担。

## 3. タブ1 — 項目ごと（ツリー目次）

Notion 風の折りたたみ。**目次構造**は `index.json` で定義（下記「データ構造」）。

### 3.1 目次ツリー（最終イメージ・拡張可）

大枠カテゴリの例（v0.6 ではこのうち **20 記事分** に絞って `index.json` を埋める）:

- **はじめに** — RefBoard とは、初期セットアップ、画面構成、ショートカット  
- **チーム・選手** — チーム CRUD、カラー/エンブレム、ロスター、退団  
- **試合管理** — 作成・メンバー追加、ゴール/アシスト/手動編集/Undo、交代・カード、ハーフ/延長/PK、終了・再編集・キャンセル  
- **複数審判** — 編集/閲覧、ロック引き継ぎ、バッジの読み方、切断時  
- **データ** — 履歴、統計、編集ログ、CSV/JSON エクスポート  
- **設定** — 言語、表示、ショートカット、リセット  
- **トラブルシューティング** — ヘルスチェック、エラーコード、保存失敗、接続、ログ  
- **開発者向け**（任意・後追い）— i18n、イベント、DB、コントリビュート

## 4. タブ2 — やりたいことから逆引き

検索ボックス ＋ **カテゴリフィルタ**（すべて / 試合 / チーム / データ / トラブル等）＋ **リスト**。各項目は **「動詞＋目的語」** 形式。

### 4.1 逆引きカテゴリ例

- **緊急度高** — 誤ゴール、誤スコア、ロック奪取、切断、サーバーダウン不安  
- **試合中** — ゴール、アシスト、オウン、交代、イエロー/レッド、PK、ロスタイム等  
- **試合の準備** — 新規試合、再開、メンバー、日時変更、キャンセル  
- **チーム管理** — 新規チーム、改名、色、ロスター追加/削除、退団記録  
- **データ確認** — 履歴、戦績、ランキング、監査、Excel、バックアップ  
- **複数審判** — 閲覧のみ、引き継ぎ、編集中表示、放置  
- **設定** — 英語化、時計形式、オートセーブ頻度、リセット  
- **トラブル** — 代表エラーコード、オートセーブ失敗、ヘルス赤、無反応、文字化け  

クリックで右ペインに同じ Markdown 記事を表示（タブ1 と **記事ファイルを共有**）。

## 5. 記事フォーマット（共通）

各 `.md` は次を **推奨セクション**として含める（v0.6 実装時にテンプレ化してもよい）。

1. **このページでわかること**（1〜2 文）  
2. **前提条件**（編集ロック、試合選択など）  
3. **手順**（番号付き。ショートカット表記）  
4. **やった後どうなる？** — できること / 注意 / できなくなること（再編集で戻る等）  
5. **よくある質問**  
6. **関連項目**（他記事 ID へのリンク）  
7. **キーボードショートカット**（該当時）  
8. **フッター**: 「この機能を今すぐ実行」→ `actionUrl` に基づき `vue-router` で遷移。`matchId` 未選択時は試合一覧へ誘導＋トースト。

### 5.1 メタデータ（YAML フロントマター案）

実装時にパーサで読み取り、検索インデックス・関連リンク・実行ボタンに利用。

```yaml
---
title: ゴールを記録したい
category: in_match
tags: [ゴール, 得点, シュート]
related: [match_record_assist, trouble_undo_goal]
shortcut: G
actionUrl: "#/workspace/matches/:matchId"   # 実ルートは実装時に固定（ハッシュルータ）
errorCode: null
---
```

**注意**: `actionUrl` は本リソースの **hash ルータ**（`#/workspace/...`）に合わせる。記事内の「オウンゴール」等は実装と照合し、未実装フローは記事で「未対応」と明記する。

## 6. データ構造

NUI バンドルに同梱する **言語別ディレクトリ**（i18n のロケールと揃える）。

```
web/src/help/
├── ja/
│   ├── index.json           # ツリー目次
│   ├── reverse_index.json # 逆引きカテゴリ + items
│   └── articles/
│       └── *.md
├── en/
│   ├── index.json
│   ├── reverse_index.json
│   └── articles/
│       └── *.md
└── assets/                  # v0.7 以降で本格利用
    ├── screenshots/
    └── animations/
```

### 6.1 `index.json`（ツリー）スキーマ例

```json
{
  "tree": [
    {
      "id": "intro",
      "icon": "🚀",
      "title": "はじめに",
      "children": [
        { "id": "intro_what", "title": "RefBoardとは", "article": "intro_what_is_refboard.md" }
      ]
    }
  ]
}
```

ネストは `children` の再帰で表現。

### 6.2 `reverse_index.json` スキーマ例

```json
{
  "categories": [
    {
      "id": "urgent",
      "icon": "🆘",
      "title": "緊急度高",
      "items": [
        {
          "id": "undo_goal",
          "title": "間違えてゴールを記録してしまった",
          "article": "trouble_undo_goal.md",
          "tags": ["ゴール", "取消", "Undo"],
          "actionUrl": "#/workspace/matches/:matchId"
        }
      ]
    }
  ]
}
```

`tags` は検索用。`actionUrl` の `:matchId` は実行時に現在の `route.params.id` で置換。

## 7. 検索

- **ライブラリ**: `fuse.js` でファジー検索（タイトル・tags・本文の重み付け）。  
- **インデックス**: ビルド時または初回表示時に、全記事（＋逆引きタイトル）をフラット化して `Fuse` に渡す。  
- **UI**: 検索バーはタブ上または共通ヘッダ。結果行に **「項目ごと / 逆引き」バッジ**。

---

## 8. コンテキストヘルプ（`?`）

- **コンポーネント**: 例 `HelpTriggerButton`（props: `contextId`）。  
- **挙動**: `contextId` に紐づく記事 ID リストを `reverse_index` または別 `context_map.json` で定義し、**スライドインパネル**に一覧→選択で本文表示。  
- **配置（v0.6 最小）**: `MatchDetail` / `TeamManage` / `DataManage` / `Settings` のヘッダ右上。

---

## 9. エラーからヘルプへ

- **Toast 拡張**: ACK / 通知に `code`（例 `E1003`）があるとき **「解決方法を見る」** を表示。  
- **ルート**: `#/workspace/help/error/E1003` のように **エラーコード直リンク** → 該当トラブル記事を表示。  
- **整合**: [error_handling.md](error_handling.md) のコード表と記事 `trouble_e1003_*.md` を 1:1 で紐づける（文言は `lock_held` 等の実キーに合わせる）。
