# Sprint 07 — ヘルプ執筆中の UI/UX 気づきメモ

**用途**: v0.6.0 でアプリ内ヘルプの記事を書く過程で、「説明が長くなった」「前提が多い」「エラー文言が分かりにくい」など **プロダクト改善の種** をここに追記する。v0.9.1 以降の修正タスクの元ネタとする。

**運用**: 日付と 1〜3 行でよい。コード変更が不要なら「記事だけで吸収」と書いてクローズしてもよい。

---

## 記録

- **2026-05-08（Phase C）**: `team_manage` / `data_manage` 用の関連記事が Phase A 時点で存在せず、`context_map.json` で空配列になった。「関連記事なし」表示は Phase D 完成までの暫定で、ユーザー目線では `?` を押した期待を裏切る。Phase D の記事順序を「intro / team / data 系を最優先」に組み替えるか、Phase D 完了まで `team_manage` / `data_manage` の `?` ボタン自体を非表示にする選択肢もある（後者は今回採用せず、空表示で文書化に留めた）。
- **2026-05-08（Phase B）**: 検索を実装してわかったこと → 記事 12 本だと閾値 0.4 でも本文一致が「揺れる」（例: `breakdown` のような英語キーで日本語記事がヒットしないケース）。Phase D で記事 20 本に増えた段階で `threshold` / `minMatchCharLength` を再評価したい。当面は `tags` を厚めに付ける運用で吸収。
- **2026-05-08（Phase A 後半）**: PK 戦のキャンセル / 先攻チーム間違いの取り消し UI が無い。`match_penalty_shootout` 記事で「未実装」と書く以外に逃げがなかった。Sprint 10 候補: `current_half=pk` に入る前のロールバックボタンと、PK 戦そのもののキャンセル経路。
- **2026-05-08（Phase A 後半）**: ロスタイム表記（`45+2` 等）が時間欄に入れられず整数の分で代用、と記事に書く必要があった。`match_record_goal` の FAQ で吸収したが、UI 側で `+` 表記を許容する小改修を v0.7 系で検討したい。
- **2026-05-08（Phase A 後半）**: 手動スコア編集で **PK 内訳を直せない**ことが、`match_penalty_shootout` / `match_manual_score_edit` の双方で「未実装」として現れた。実害は低いが、運用ルールで縛るか、PK 用の手動編集ダイアログを別途用意するか v0.7 系で判断したい。
- **2026-05-08（Sprint 09 / 試合中ヘルプ）**: ゴール・アシスト記事で **未実装・制約を先に書く**と読者の手戻りが減る（オウンゴール専用フローなし、アシスト後追いの専用 UI なし、ダブルアシスト不可）。逆に「あとで実装」とだけ書くと期待値が残るので、**いつ議題化したか**（`sprint_07_uiux_findings` 等）への参照を一文入れるとよい。
- **2026-05-06（試合管理）**: 選手一覧の「状態」は表示のみで、**交代・イエロー/赤**はイベントタイムライン側の操作から入る。ユーザー要望: 状態セルをタップして「出場→警告中→…」のようにサイクル切替できると発見性が上がる。実装する場合は **監査ログ付きの専用 NetEvent**（いまのカード／交代と同列）が必要で、スプリントを分けて検討したい。
- **2026-05-06**: オートセーブ失敗時の UI では「再試行」導線が記事前提だが、NUI 側の再試行ボタン配線は未実装のため、記事では「設定 → ヘルスチェック」「管理者にログ共有」に寄せて書いた。v0.7 以降でボタン実装と記事を揃えたい。
- **2026-05-06**: ゴール取り消し記事で `Ctrl+Z` を触れないようにした（キーバインド未配線のため）。ショートカットを増やすなら記事・ツールチップ・設定画面の三方で同期させる必要あり。
