# jp-deliveryjobv2 開発日記（2026-05-05）

nek_deliveryjobV2 日本語化パッケージの経緯と、運営・後任が追いやすいよう決定事項をまとめる。

## パッケージの位置づけ

- 本リポジトリの `AGENTS.md` では **jp-\* 単体 MOD（フレームワーク非依存）** を原則としている。
- 本パッケージはオリジナルが **ESX / QBCore + ox_lib + ox_target 依存** のため **フォーク／ローカライズ配布** として扱う。
- `README.md` / `INSTALL.md` で依存関係を明示済み。**v2.1.2-jp 以降**は `jp-deliveryjobv2` フォルダ直下がリソースルート（`ensure jp-deliveryjobv2`）。

## コミット履歴（要点）

### 5547ec0 — 初回取り込み・日本語化（v2.1.0-jp 相当）

- `config/config.lua`: ロケール全面日本語、`blip_destination` 追加、ブリップ名「配達センター」、日本語コメント。
- `fxmanifest.lua`: `version` / `author` / `description` を日本語版向けに更新。
- `Data.sql`: ESX ジョブラベル「配達員」。
- `html/`: 言語・UI 文言を日本語化。
- `client/` / `server/`: 主要コメントの日本語化。
- **修正**: `server/bridge.lua` に `getIdentifiers` を実装（元コードでは Webhook 用に未定義だった）。
- **修正**: `playerDropped` で `src` を明示。
- **修正**: `server/utils.lua` の Discord 表記・日付形式・フィールド名の日本語化と nil 安全化。
- ルート文書: `README.md`, `INSTALL.md`, `CHANGELOG_JP.md`、`LICENSE` に日本語メモ追記。

### bb7ec89 — ルート名・後方互換・文言調整（v2.1.1-jp）

- `Config['Delivery']['Routes']` を `{ name, stops }` 形式に拡張。既定の `name` は GTA V 地区寄りの表記（ヴェスプッチビーチ周辺 / ロックフォード〜ダウンタウン / ヴァインウッドヒルズ）。
- `client/job.lua`: `NormalizeDeliveryRoutes()` により **旧形式（vec3 の配列のみ）** を起動時に `{ name = "ルート N", stops = ... }` へ変換し後方互換を維持。
- NUI: `START_ROUTE` に `routeName` を追加。ヘッダは `配達ルート: {name}`。`CLOSE_UI` で見出しを既定に戻す。
- ロケール: Webhook 用「不正検知」、スポーン失敗時の行動が分かる文面、`error_starting` の具体化。
- `INSTALL.md`: QBCore の `payment` と `FinalPayout` が別建てである旨を注釈。トラブルシュートは特定の通知文に依存しない書き方に変更。
- `fxmanifest.lua`: `version` を `2.1.1-jp` に更新。

## 配布・タグ運用（参考）

- リリース追跡用に Git タグ `v2.1.1-jp` を付与可能（`git tag -a v2.1.1-jp -m "日本語化版 v2.1.1-jp"` → `git push origin v2.1.1-jp`）。
- GitHub Releases では `CHANGELOG_JP.md` の該当節を本文に転記し、**`jp-deliveryjobv2` フォルダ**を zip 化して添付するなど、git に不慣れな利用者向けに配布できる。

### 構成フラット化（v2.1.2-jp）

- ネスト `jp-deliveryjobv2/nek_deliveryjobV2/` のままだと、環境によっては内側リソースがスキャンされず `ensure nek_deliveryjobV2` も失敗する事例があった。
- 対策として **`jp-deliveryjobv2` 直下に `fxmanifest.lua`・`client/` 等を配置**し、リソース名を **`jp-deliveryjobv2`** に統一。`exports` も同名。
