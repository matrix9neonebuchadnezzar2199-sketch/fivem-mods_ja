概要

マスター依頼の「ヴェガ出発 → 戦闘 → 脱出／時間切れ／死亡／DC／パワープレイ」全シナリオのコードレビュー（前段会話）で挙げた優先度高〜中項目を順に反映した。

  • #1 タイムアウト時の Result：Session.Destroy('timeout') から未脱出メンバーごとに Result.Discard(s, src, 'timeout') を呼び、mrd9_result_logs.result='timeout' を残す。arena_wiped/all_lost でも同じ経路で 'died' を Discard する。extractedInventory がある脱出済みプレイヤーは二重記録しない。
  • #1 続き：client/main.lua で extracted 以外（died / all_lost / arena_wiped / timeout / out_of_zone）でも Result NUI を見せ終わるまで LS 帰還を保留（90s フォールバック付き）。死亡演出 NetworkResurrectLocalPlayer は従来通り即実行。
  • #2 PlayArea：Config.Mission.playArea（center / maxRadius=1200 / warnSec=20 / graceSec=30）と新規 server/playarea.lua を追加。境界外にいるプレイヤーへ警告 → 50 秒で Session.RemovePlayer(src, 'out_of_zone')。範囲内に戻ればカウンタリセット。
  • #3 admin kick：/m9_admin_session_kick <playerId> を追加。ACE jp-meridian9.admin 必須。Session.RemovePlayer(target, 'forced') 経由で既存の Result.Discard 'forced' に乗る。
  • #4 タイムアウト検出：cleanupIntervalSeconds を 60→5 に短縮（負荷は無視できる）。endsAt 到達からの遅延を最大 5 秒に。
  • #6 _hudKillSeen 肥大化：セッション中の累積を Config.HUD.killSeenCap=1000 で頭打ち、古い順 1/4 を削除する LRU 風。netId 再利用による誤集計はリスク低下、HUD のキル合計は概算で十分のため許容。
  • #8 タイマー補間：html/hud.js で hud:state の extractSeconds を performance.now() 基準でローカル補間。setInterval(250ms) で減算、次の broadcast で上書き同期。サーバ broadcast 抜けで秒が止まって見える事故を緩和。

スキップ項目（後ほど検討）

  • #5 死亡時 NUI とフェードの競合：#1 のテレポート保留拡張で「Result NUI を見せてから帰還」になったため、競合自体は緩和されている見込み。実機で「死亡 → Resurrect → Result NUI → ESC で帰還」が滑らかか目視確認が必要。問題が出たら別途調整。
  • #7 境界外ゾンビ湧き：#2 の out_of_zone 排除で境界外滞在自体が 50 秒で終わるため自然解決見込み。Survival の spawnAroundPlayer ロジック自体には手を入れていない。

他コードへの影響と注意

  • SQL マイグレーション必須：運営環境では 2026-05-16_mrd9_result_logs_timeout_outofzone.sql を適用しないと Result.Discard('timeout') 実行時に ENUM 制約違反で INSERT 失敗する。
  • Config 後方互換：新フィールド（playArea / killSeenCap）はいずれも nil チェック＋デフォルトを実装側で持つため、運営の旧 config.lua のままでも動作する。cleanupIntervalSeconds も nil 時は 60 にフォールバック。
  • playArea 中心座標は暫定値：vector3(4790.0, -5170.0, 10.0) は Cayo 概略中心。ExtractPoints 5 ヶ所（監視塔 / ヘリポート / テント / 飛行場 / 配電施設）が全て maxRadius=1200 内にあるかは実機要確認。外れていれば運営が config.lua で調整。
  • Result.Discard の二重発火回避：Session.RemovePlayer(src, 'out_of_zone') が最後の 1 人なら直後に Destroy('all_lost') が走るが、members から既に除外されているため Destroy 内の Discard ループは空回り。二重 INSERT は起きない。
