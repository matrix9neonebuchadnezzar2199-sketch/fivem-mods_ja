## A. 実機テストが必要な機能（未検証の整理）

### A-1: サブフェーズ A（リザルト方式・最重要）

| ID | 検証項目 | 期待挙動 | 確認方法 |
|-----|----------|----------|----------|
| A-1-a | 通常脱出 → リザルト → 報酬付与 | ルートは論理在庫のみ。リザルトの `total` に応じ `mrd9_credit` または現金 | 数点回収して脱出、`ox_inventory` / 残高確認 |
| A-1-b | 空脱出 | items 空、`extractionBonus` のみ、`payout` 表示 | 未回収で脱出 |
| A-1-c | Subject-0 持ち帰り | CONFISCATED 表示、`fictionBounty` 加算、細胞片は実インベントリに入らない | `data_chip`（`fictionTag = subject_zero`）を回収して脱出 |
| A-1-d | 死亡 | 論理在庫破棄、赤基調・空リスト、`mrd9_result_logs` に `died` | 任務中死亡 |
| A-1-e | 切断 | 同上に近い挙動、`disconnect` 記録、再接続で F8 異常なし | 任務中にクライアント強制終了 |
| A-1-f | `FlattenMissionInventory` | `{main,safe}` と旧フラット双方で集計が壊れない | 在庫パターンを変えて再起動・脱出 |
| A-1-g | `mrd9_result_logs` | `extracted` / `died` / `disconnect` が期待どおり記録 | DB 照会（`sql_diagnostics.md` 参照） |
| A-1-h | `/m9_cashout` | `ox_inventory` かつ `directCashout=false` のときのみ有効、それ以外は拒否 | コマンド実行 |

**観察**: B-b 後は `grant` から `AddItem` しないため、`failed_inventory_full` は理論上ほぼ発生しない。論理在庫上限の要否は A-1-a の運用観察で判断。
