DB 障害時のフォールバック実装と HUD 右上時計の撤去

時刻 00:14 JST Commit pending

変更ファイル

  • 📝 jp-meridian9/server/loot/grant.lua（writeLog を pcall + MRD9.Log 化）
  • 📝 jp-meridian9/server/stats.lua（Update / LogMission を pcall + MRD9.Log 化）
  • 📝 jp-meridian9/server/hud.lua（buildPhaseCPayload から clock を撤去）
  • 📝 jp-meridian9/html/index.html（.mrd9-clock-block を撤去）
  • 📝 jp-meridian9/html/hud_preview.html（同上）

  • ➕ jp-meridian9/docs/2026-05-17_開発日記.html

概要

マスター実機ログで Table 'fivem_db.mrd9_loot_logs' doesn't exist / 'fivem_db.mrd9_result_logs' doesn't exist が連続流出。原因はテーブル未作成（sql/install.sql 未投入または別 DB 投入）と判断。プレイは継続できる構造だが、運営デバッグの邪魔と監査ログ欠落を防ぐため、ホットパスの DB 書込を pcall 化して失敗を MRD9.Log にフォールバックさせた。範囲は ホットパス限定（loot/grant.lua の writeLog、stats.lua の Update / LogMission）。contract.lua は契約状態が DB 書込成功と一致する必要があるためフェイルファスト維持。

並行して、HUD 右上の現地時計（#mrd9-clock）を撤去。サーバ側で os.date('*t') から OS 実時間を埋めていた点が世界観に矛盾（ストーリー §「次元の歪みで時間軸が切り離された島」）し、また右下の「制限時間」と表示が重複していたため。renderClock / tickClock / CSS / プレビュー HTML まで一括整理。

他コードへの影響と注意

  • DB 復旧手順（マスター側作業）：
    1. mysql -u <user> -p fivem_db < jp-meridian9/sql/install.sql
    2. mysql -u <user> -p fivem_db < jp-meridian9/sql/migrations/2026-05-15_mrd9_result_logs_forced.sql
    3. mysql -u <user> -p fivem_db < jp-meridian9/sql/migrations/2026-05-16_mrd9_result_logs_timeout_outofzone.sql
    4. SHOW CREATE TABLE mrd9_result_logs\G で ENUM が 'extracted','died','disconnect','forced','timeout','out_of_zone','unknown' になっていることを確認
    install.sql は全 CREATE TABLE IF NOT EXISTS なので既存データは壊れない。
  • pcall 化の範囲限定理由：contract.lua の Sign / Suspend / Terminate は IsContracted が DB の真実と一致する前提で機能している。pcall で失敗を握りつぶすと「DB 書込未完了で active 扱い」になり未契約者のセッション侵入を許す。main.lua の admin_list 系は運営の手動 SELECT で副作用が無く、エラーが出るほうがむしろ運営に異常を伝えやすいため pcall しない。
  • NUI 後方互換：サーバが clock を送らなくなっても、hud:state の handler は p.clock を参照しないので問題なし。古いクライアントが新サーバから受信しても renderClock の null チェックがあるため害なし（ただし古いクライアントは古い #mrd9-clock に --:-- が残る—deploy で同時更新前提）。
  • DB 復旧後の挙動：テーブルが復活すれば pcall は成功側に戻り、自動でログ書込が再開する。コード再変更不要。

未完了 / 次タスク

  • マスター: DB 復旧 3 ファイル投入 + SHOW CREATE TABLE で ENUM 確認
  • 実機: refresh; restart jp-meridian9 後、右上から時計が消え制限時間のみになっていること
  • 実機: DB 接続を意図的に切って pickup・extract した時、サーバコンソールに [jp-meridian9] mrd9_loot_logs insert failed: ... が出てもプレイが継続すること（任意検証）
